# profile

Контракт CLI-команды `profile`: просмотр и управление именованными YAML-профилями в
каталоге пользователя.

## Назначение

Создавать, просматривать, редактировать и удалять файлы профилей; назначать профиль по
умолчанию (файл `default`). Команда **не** вызывает [SCM API][SCM-PLATFORM-TERM] и **не**
подставляет профиль в резолв глобальных флагов **этого же** запуска (формат YAML и порядок
резолва для остальных команд — [профили][profiles.md]).

## Синтаксис

```text
githerd profile [profile-name]
githerd profile use <profile-name>
githerd profile create <profile-name> [--from <from-profile-name>] [--edit]
githerd profile drop <profile-name>
githerd profile edit <profile-name>
```

Глобальные опции наследуются с корня CLI ([глобальные параметры][cli-index.md]). Флаги
`upstream`, `host` и `token` для `profile` **не обязательны**.

Глобальный флаг `--profile` для `githerd profile` и **всех** подкоманд **запрещён**:
если опция передана (в том числе с несуществующим именем), это ошибка настроек, exit `1`,
до любых операций с файлами в каталоге профилей.

## Имена профилей

Имя профиля — stem файла `<имя>.yaml` в [каталоге профилей][profiles.md]. Учитываются
только файлы с расширением `.yaml` (не `.yml`).

| Правило | Требование |
| ------- | ---------- |
| Символы | Буквы, цифры, `-`, `_` |
| Запрещено | `/`, `\`, `..`, пустая строка после trim |
| Зарезервировано | Имя `default` (конфликт с файлом-указателем) |
| Регистр | Учитывается |

Нарушение правил имени — ошибка до записи на диск, exit `1`.

## Каталог профилей

Пути — [каталог и файлы][profiles.md] в platform SSOT.

При `create` и `use`, если каталог `~/.config/git-herder/` отсутствует, продукт
**создаёт** его перед записью.

## Битый указатель `default`

Если файл `default` существует, имя после trim непустое, а `<имя>.yaml` отсутствует —
см. [битый указатель в profiles.md][profiles-broken-default].

Для дерева `profile`: предупреждение в журнал (`level=warn`) и **то же сообщение** на
консоль через pterm; exit `1` **не** выставляется из‑за этого условия. В списке профилей
ни одна строка **не** помечается как профиль по умолчанию.

## Поведение без подкоманды

### `githerd profile`

Выводит на stdout перечень имён всех `*.yaml` в каталоге профилей, сортировка —
лексикографическая по имени (байты/кодировка как в локали ФС ОС; для тестов фиксировать
ожидаемый порядок по ASCII-именам).

Профиль, имя которого совпадает с содержимым `default` (после trim) и для которого
существует `<имя>.yaml`, выделяется через pterm при интерактивном TTY; без TTY — суффикс
"(default)" в той же строке.

Код выхода: `0`.

### `githerd profile <profile-name>`

Читает `~/.config/git-herder/<profile-name>.yaml` и печатает содержимое на **stdout**.
Перед выводом к полям-секретам применяют [маскировку секретов][logging-redact] (как для
журнала: литерал `***` и остальные правила SSOT).

Профиль не найден — сообщение пользователю, exit `1`.

## Подкоманда `use`

```text
githerd profile use <profile-name>
```

`<profile-name>` обязателен. Файл `<profile-name>.yaml` должен существовать; иначе exit `1`.

Записывает в `~/.config/git-herder/default` одну строку: имя профиля и символ перевода
строки (`\n`). Чтение `default` — trim по краям ([profiles.md][profiles.md]).

Успех: exit `0`.

## Подкоманда `create`

```text
githerd profile create <profile-name> [--from <from-profile-name>] [--edit]
```

| Условие | Действие |
| ------- | -------- |
| `<profile-name>.yaml` уже есть | exit `1` |
| Без `--from` | Создать файл с минимальным содержимым: `root: {}` |
| С `--from <from-profile-name>` | Копия существующего файла; источник отсутствует — exit `1` |
| Флаг `--edit` | После создания файла — тот же поток, что у [подкоманды `edit`](#подкоманда-edit) |

Успех: exit `0`.

## Подкоманда `edit`

```text
githerd profile edit <profile-name>
```

Профиль должен существовать; иначе exit `1`.

| `$EDITOR` | Поведение |
| --------- | --------- |
| Непустой | Запуск редактора с одним аргументом — абсолютный путь к `<profile-name>.yaml` |
| Пустой | Понятное сообщение на консоль и полный абсолютный путь к файлу; exit `1` |

После завершения редактора: если файл не парсится как YAML — ошибка настроек, exit `1`.
Семантика ключей (`token` только в `root` и т.д.) проверяется при загрузке профиля для
**других** команд, не обязательно в момент `edit`.

Успех: exit `0`.

## Подкоманда `drop`

```text
githerd profile drop <profile-name>
```

Профиль должен существовать; иначе exit `1`.

Если `<profile-name>` совпадает с содержимым `default` (после trim) — удаление
**запрещено**, exit `1`; подсказка сначала выполнить `profile use` с другим именем.

Иначе:

| Сессия | Подтверждение |
| ------ | ------------- |
| Интерактивный TTY | Запрос через pterm (да/нет); отказ — файл не удаляется, exit `0` |
| Не TTY | Удаление **без** подтверждения |

При успешном удалении: exit `0`.

## Коды завершения

Общие коды — [глобальные параметры CLI][cli-exit-codes]. Для `profile`:

| Код | Условие |
| --- | ------- |
| `0` | Успех; отмена `drop` пользователем |
| `1` | Нет профиля; неверное имя; глобальный `--profile` в этом дереве; `drop` для текущего default; невалидный YAML после `edit`; пустой `$EDITOR` при `edit`/`create --edit` |
| `2` | Неверный вызов CLI (нет аргумента, неизвестная подкоманда) — [Cobra][adr-cobra] |

Битый `default` сам по себе не даёт exit `1` в дереве `profile`.

## Поток выполнения

1. Разбор argv (глобальные флаги + подкоманда).
2. При необходимости — проверка `default` и предупреждение о битом указателе (только
   дерево `profile`).
3. Операция с файлами в `~/.config/git-herder/` согласно подкоманде или режиму без
   подкоманды.

## Инварианты

- Изменения только в каталоге профилей и файле `default`; SCM API не вызывается.
- Секреты при выводе содержимого профиля на stdout маскируются по [logging.md][logging-redact].
- Текущий default-профиль удаляют только после смены через `use`, не через `drop`.
