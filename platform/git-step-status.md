# Ход долгого шага git

Пока команда ждёт долгий процесс `git`, на stderr видна одна строка хода.
Итог по объекту остаётся на stdout. Строка — текст продукта: вывод процесса
`git` в неё не входит.

## Трассировка вверх

- [Обратная связь в терминале][terminal]

## Когда строка есть

Строку показывают `sync`, `clone`, `publish`, `merge`, `switch`, `pull`,
`push`, `fetch` и `remote` на долгих шагах `git`.
Какие это шаги и какое слово шага печатается, задаёт спецификация команды.

Строки нет на коротком вызове `git`: отбор копий, чтение атрибута, список
неслитых файлов. Нет её и у создания репозитория через API SCM. Очередь
повторов строку не рисует.

Пока у объекта есть следующая попытка, итоговую строку не пишут. Строка
хода на повторной попытке есть.

## Строка

Одна строка UTF-8. Поля разделяет один пробел:

```text
<шаг> <сделано>/<всего> <метка>[ attempt <n>] <м>:<сс>
```

`<шаг>` — одно или несколько английских слов. Их задаёт команда.

`<сделано>` — сколько объектов этой очереди уже получили итоговую строку.
`<всего>` — сколько объектов поставлено в очередь в начале прогона.
Объекты, отсеянные до очереди, в счёт не входят.

`<метка>` — тот же видимый идентификатор, что команда печатает в итоге
после знака, без знака и без текста ошибки. Как собирается путь или полное
имя, остаётся в спецификации команды.

`attempt <n>` есть только со второй попытки объекта. `<n>` — номер попытки,
счёт с единицы: вторая попытка — `attempt 2`. На первой попытке этих слов
нет. Время шага на новой попытке начинается заново.

`<м>` — целые минуты с запуска процесса `git` этого шага, без ведущего
нуля. Минуты могут быть больше 59. `<сс>` — секунды, всегда две цифры.

Пример. Вторая попытка получения, три копии уже с итогом, в очередь
поставили двенадцать, прошло сорок одна секунда:

```text
pull 3/12 documentation/architecture attempt 2 0:41
```

Смена шага заменяет строку. На первой попытке того же шага слова
`attempt` нет:

```text
push 3/12 documentation/architecture 0:05
```

## Терминал и обычный вывод

Если stderr — терминал, строка перерисовывается на месте не реже раза
в секунду. Перед печатью итога объекта на stdout её стирают.

Если stderr не терминал, в начале шага печатается одна обычная строка
с `0:00`. Её не обновляют и не стирают.

## Чего в строке нет

Нет URL, токена и userinfo. Зеркало журнала при `-V` эту строку не
заменяет и не выключает. Формат зеркала — [журнал][logging].

Прогресс-бар страниц и обогащения SCM здесь не задаётся. Он остаётся
в [оркестрации][scm-index].

## Не здесь

- Перечень шагов и слово шага конкретной команды.
- Знаки и текст итога.
- Куда пишется stdout и stderr процесса `git`.
- Повтор объекта и `--on-error`.
