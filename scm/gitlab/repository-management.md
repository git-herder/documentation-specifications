# Управление репозиториями (GitLab)

Контракт компонента **GitlabRepositoryManagement**: проверить проект и
группы на GitLab, создать недостающие группы цепочки и создать проект.
Запросы идут через [HTTP-транспорт][transport]. Повтора запроса здесь нет.

## Трассировка вверх

- [Публикация локальных рабочих копий в SCM][publish]
- [Обобщённая карточка репозитория][card] — поля `path` и `name`
- [ADR-26101703][adr-http] — обёртка над `net/http`

## Путь

Полный путь проекта — сегменты `path` и `name` через `/`. `path` — один
или больше сегментов групп. `name` — путь проекта внутри последней
группы. Пустой `path` или пустой `name` — ошибка контракта до HTTP.
Проект прямо в пространстве пользователя этот контракт не создаёт.

В `:id` полный путь передаётся в кодировке URL: `/` становится `%2F`.
Пример: `group/sub/project` → `group%2Fsub%2Fproject`.

## Проверка проекта

|              |                                        |
| ------------ | -------------------------------------- |
| Метод и путь | `GET /api/v4/projects/:id`             |
| `:id`        | полный путь проекта в кодировке URL    |

`200` — проект для вызывающего есть. `404` — нет. Скрытый чужой проект
платформа тоже отдаёт как `404`. Прочий код — ошибка вызова.

## Проверка группы

|              |                                     |
| ------------ | ----------------------------------- |
| Метод и путь | `GET /api/v4/groups/:id`            |
| `:id`        | полный путь группы в кодировке URL  |

Путь группы — префикс `path` целиком, не последний сегмент отдельно.
`200` — группа есть, числовой `id` ответа дальше используется как
`parent_id`. `404` — группы нет. Прочий код — ошибка вызова.

## Создание недостающих групп

Префиксы `path` идут слева направо: первый сегмент, затем два сегмента,
и так до всего `path`. Для каждого префикса — проверка группы.

- `200` — группа есть. Её числовой `id` — родитель следующего префикса.
- `404` — `POST /api/v4/groups`. Поля `name` и `path` равны последнему
  сегменту префикса. У первого префикса `parent_id` нет. У следующего
  `parent_id` — числовой `id` предыдущей группы. Успех — `201`. Числовой
  `id` ответа — родитель дальше по цепочке.
- Прочий код — ошибка вызова. Следующие префиксы не обрабатываются.

Видимость и описание группы компонент не передаёт.

## Создание проекта

`POST /api/v4/projects`. Поля `name` и `path` равны `name` карточки.
`namespace_id` — числовой `id` группы, чей путь равен всему `path`.
Других полей компонент не передаёт.

Успех — `201`. Прочий код — ошибка вызова. Если проверка дала `404`
из-за скрытого проекта, создание завершается ошибкой API. Компонент не
подменяет её успехом.

## Не здесь

- Повтор неуспешного вызова. Транспорт ошибку не повторяет.
- Код выхода команды и политика «репозиторий уже есть».
- Как из каталога workspace собираются `path` и `name`.
- Изменение и удаление проекта или группы.
