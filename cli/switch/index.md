# switch

Команда `switch` переключает отобранные рабочие копии из `--workspace`
на ветку `<branch>`. На каждую копию приходится один вызов `git switch`.
Очереди повторов нет. Замысел —
[массовые локальные git-операции][mass-ops].

## Контракт

### Синтаксис

```text
githerd [глобальные опции] switch <branch> [start-point] [опции switch]
```

Глобальные флаги — [глобальные параметры CLI][cli-index]. Команда не
вызывает API SCM: `upstream` и `token` не обязательны. Если они заданы,
команда их не использует — [подключение к SCM][cli-scm].

`<branch>` — обязательный позиционный аргумент: имя ветки.
`[start-point]` — необязательный позиционный аргумент: ревизия, от
которой создаётся ветка. Оба значения команда читает после резолва.
Источники у каждого только два: аргумент, иначе ключ блока `switch` в
[профиле][profiles] (`branch` или `start-point`). Родительские блоки и
`root` эти ключи не дают. Нет `<branch>` или строка пустая — код `1`,
поиск копий не начинается. Нет `[start-point]` — операнд в `git` не
передаётся, точка старта копии — её `HEAD`. Пустая строка
`[start-point]` — код `1`, до поиска. Значение `[start-point]` есть, а
ни `--create`, ни `--force-create` не заданы — тоже код `1`, до поиска.

`--workspace` / `-w` — каталог, в котором ищутся копии. Приведение к
абсолютному пути — [правила workspace][cli-workspace]. Команда этот флаг
не игнорирует.

### Опции команды

| Имя | Назначение |
| --- | ---------- |
| `--qn` | Повторяемая строка, по умолчанию не задана. Условие на имя копии. Сопоставление — [поиск рабочих копий][resolver]. |
| `--qp` | Повторяемая строка, по умолчанию не задана. Условие на путь копии. Сопоставление — [поиск рабочих копий][resolver]. |
| `--interactive` (`-i`) | Логический, по умолчанию выключен. Интерактивный отбор после программных фильтров. Передаётся [поиску рабочих копий][resolver]. |
| `--all` (`-A`) | Логический, по умолчанию выключен. Не спрашивать [порог подтверждения][mass-confirm], когда копий больше 10. |
| `--create` (`-c`) | Логический, по умолчанию выключен. Создать локальную `<branch>`. Вместе с `--force-create` — код `1` до поиска. |
| `--force-create` (`-C`) | Логический, по умолчанию выключен. Создать локальную `<branch>` или пересоздать её. |
| `--discard-changes` | Логический, по умолчанию выключен. Сбросить индекс и рабочее дерево и переключиться. В `git` уходит `--discard-changes`. Вместе с `--merge` — код `1` до поиска. |
| `--merge` (`-m`) | Логический, по умолчанию выключен. Перенести локальные изменения трёхсторонним слиянием. |
| `--track` | Имя [ремота][REMOTE-TERM] для вышестоящей ветки. Ключ не задан — вышестоящая ветка не меняется. Флаг без значения и значение `null` в профиле — ремот `origin`. Пустая строка — код `1` до поиска. Короткой формы нет: `-t` — глобальный `--token`. |
| `--git-opts` | Повторяемая строка, по умолчанию не задана. Аргументы вызова `git switch` в [обработчике][handler], по одному на повтор. |

В профиле YAML те же ключи без `--`. Логические флаги — по
[синтаксису опций][cli-syntax]. Повтор в профиле — скаляр или
последовательность ([структура YAML][profiles-yaml]). Порядок выбора
остальных ключей — [выбор значения][resolve], здесь он не
пересказывается.

Флагов `--detach` и `--orphan` у команды нет. Неизвестная опция —
код `2` по [кодам выхода CLI][cli-exit].

`--git-https-token` — глобальный флаг, не опция `switch`. На процессы
`git` этой команды он не влияет: получения с ремота нет.

## Поток выполнения

1. Берёт параметры из Invocation. Для `<branch>` и `[start-point]`
   источники — только [синтаксис](#синтаксис). Повтор `--git-opts`: если
   флаг задан в командной строке, берётся только она, список из профиля
   не подмешивается — то же правило происхождения, что у повторяемых
   критериев ([резолв с профилем][repeat-resolve]).
2. Проверяет параметры и при ошибке завершается с кодом `1`, ничего не
   ища. Так бывает, если заданы сразу `--interactive` и `--all` — по
   [порогу подтверждения][mass-confirm]; если нет `<branch>` или имя
   ветки пустое; если `[start-point]` задан без `--create` и без
   `--force-create`; если строка `[start-point]` пустая; если заданы
   сразу `--create` и `--force-create`; если заданы сразу
   `--discard-changes` и `--merge`; если строка `--track` пустая; если в
   `--git-opts` есть [запрещённый аргумент][git-deny].
3. Ищет рабочие копии в `--workspace` через
   [поиск рабочих копий][resolver] и передаёт ему `--qn`, `--qp` и
   `--interactive`. Если не заданы ни `--create`, ни `--force-create`,
   функция отбора через **GitCliRunner** проверяет локальную ветку
   вызовом `git rev-parse --verify --quiet` с операндом
   `refs/heads/<branch>`. Код `0` — копия остаётся. Код `1` — ветки нет,
   копия отбрасывается, строка [итога][result] по ней не печатается.
   Это не ошибка функции. Любой другой код и сбой запуска `git` —
   ошибка функции, код `1` по [резолверу][resolver]. Аргументы
   `--git-opts` этому вызову не передаются, `--no-guess` тоже.
   Если задан `--create` или `--force-create`, функция отбора не
   передаётся.
4. Если после отбора копий нет, завершается с кодом `0`.
5. Сверяет число копий, которые пойдут в прогон, с
   [порогом подтверждения][mass-confirm]. Отказ — код `0`.
6. Обрабатывает оставшиеся копии по порядку обнаружения, без
   [очереди повторов][queue]. `--retries-number` команда не применяет.
   Ошибка копии сразу подчиняется `--on-error`: `abort` печатает
   [итог][result] этой копии и не обрабатывает следующие; `continue`
   переходит к следующей. Смысл значений — [флаг][cli-on-error]
   `--on-error`, шага повторов перед ним нет.
7. По каждой обработанной копии печатает [итог][result] один раз, когда
   обработка копии закончилась.

## Обработчик копии

Stdout и stderr процесса `git` на консоль не попадают: текст пишется в
[журнал прогона][logging]. На время `git switch` видна
[строка хода][git-step]. Слово шага — `switch`. Метка — путь из
[итога][result]. Повторной попытки нет, поэтому `attempt` в строке не
появляется. `<сделано>` и `<всего>` считаются по копиям этого прогона:
отсеянные до него в счёт не входят.

Вызовы, которые только читают состояние, не получают `--git-opts` и не
показывают строку хода. Это память входа, список неслитых имён и чтение
уже настроенной вышестоящей ветки. Короткий `git branch` строку хода
тоже не показывает.

На весь прогон одни и те же `<branch>`, `[start-point]`, флаги и список
`--git-opts`. Ревизию `[start-point]` разрешает `git` в каждой копии
отдельно. Нет такой ревизии — ненулевой код `git switch`, это ошибка
копии, а не отсев на поиске.

### Память входа

До `git switch`, по порядку. Хватает первого сбоя запуска или кода,
который ниже не назван: переключение не начинается. Знак переключения —
`❌`, текст «проверка копии не удалась». Знак вышестоящей ветки —
по [правилу шага](#вышестоящая-ветка).

1. `git symbolic-ref --quiet HEAD`. Код `0` — имя ветки, участок после
   `refs/heads/`. Иной код процесса — символической ветки нет.
2. `git rev-parse --verify --quiet HEAD`. Код `0` — идентификатор
   коммита. Код `1` — коммита нет.
3. Только при `--discard-changes`: `git status --porcelain=v1`. Хотя бы
   одна строка stdout — в дереве есть незакоммиченные изменения.

### Переключение

Продукт всегда ставит `--no-guess` до аргументов `--git-opts`. Без
`--create` и без `--force-create` локальная ветка из ветки удалённого
слежения не создаётся. Из `--discard-changes` и `--merge` в вызов входит
не больше одного. Из `-c` и `-C` — не больше одного. Имя `<branch>` стоит
сразу за `-c` или `-C`: для `git` это значение флага. Разделитель `--`
перед `<branch>` ставится только без `-c` и без `-C`. `[start-point]`
добавляется только вместе с `-c` или `-C` и только если значение задано;
тогда `--` стоит перед `[start-point]`.

```text
git switch --no-guess [--discard-changes|--merge] <аргументы --git-opts> -- <branch>
git switch --no-guess [--discard-changes|--merge] [-c|-C] <branch> <аргументы --git-opts> [-- <start-point>]
```

Дальше смотрят исход, по порядку. Хватает первого пункта.

1. Задан `--merge`. Список неслитых имён читают так же, как для знака
   `⚔️` в [итоге sync][sync-result]. Сбой запуска `git` на этом списке —
   знак `❌`, текст «проверка копии не удалась». Список непуст —
   конфликт: состояние в копии сохраняется, команда его не снимает, знак
   переключения `⚔️`. Пустой список — смотрят следующий пункт.
2. Код процесса не `0` — ошибка копии. Знак `❌`. Текст — первая
   непустая строка stderr, иначе первая непустая строка stdout, иначе
   «переключение не удалось».
3. Код `0`. Снова читают символическую ветку и идентификатор `HEAD` теми
   же вызовами, что в [памяти входа](#память-входа). Сбой запуска или
   код, которого память входа не ждёт, — знак `❌`, текст «проверка
   копии не удалась». Имя символической ветки не равно `<branch>` —
   знак `❌`, текст «переключение не удалось». Иначе знак `✔️`, если
   выполнено хотя бы одно: до вызова символической ветки не было или её
   имя было другим; идентификатор `HEAD` отличается от запомненного
   (не было идентификатора и он появился — тоже отличие); задан
   `--discard-changes` и в статусе была хотя бы одна строка. Иначе знак
   `➡️`: копия уже стояла на `<branch>`, коммит и дерево не менялись.

### Вышестоящая ветка

Знак этого шага ставится после знака переключения.

- Знак переключения не `✔️` и не `➡️` — знак шага `⏩`, текст
  «не начинался». Вызова `git` нет.
- Знак `✔️` или `➡️`, а `--track` не задан — знак шага `➡️`. Вызова
  `git` нет.
- Знак `✔️` или `➡️` и `--track` задан — чтение ниже и, если цель ещё
  не записана, `git branch`.

В третьем случае имя ремота — значение `--track`. Ожидаемая вышестоящая
ветка — `<remote>/<branch>`, одна строка.

```text
git rev-parse --abbrev-ref --symbolic-full-name refs/heads/<branch>@{upstream}
```

Код `0` и единственная строка stdout, без пробелов по краям, равна
`<remote>/<branch>` — знак `➡️`, `git branch` не вызывается. Сбой
запуска — знак `❌`, текст «проверка копии не удалась». Любой другой
исход — вышестоящая ветка ещё не равна цели, продукт вызывает:

```text
git branch --set-upstream-to=<remote>/<branch> -- <branch>
```

Код `0` — знак `✔️`. Ненулевой код и сбой запуска — знак `❌`. Текст —
первая непустая строка stderr, иначе первая непустая строка stdout,
иначе «вышестоящая ветка не записана». Получения с ремота нет: нет
локальной ссылки `<remote>/<branch>` — этот вызов и есть ошибка шага.
Переключение при этом уже выполнено.

## Передача параметров git

Список `--git-opts` уходит только в `git switch` обработчика. Память
входа, список неслитых имён, чтение `@{upstream}` и `git branch` его не
получают.

Каждое значение — один аргумент процесса, в порядке повторов флага или
элементов последовательности в профиле. Если флаг задан в командной
строке, берётся только она — [резолв с профилем][repeat-resolve].
Значение записывают через `=`, потому что оно само начинается с `-`:

```text
githerd switch feature --git-opts=--ignore-other-worktrees
```

В профиле значение — скаляр или последовательность
([структура YAML][profiles-yaml]):

```yaml
switch:
  branch: feature
  git-opts:
    - --ignore-other-worktrees
```

Пустой список в команду ничего не подставляет. Флаги продукта стоят до
этого списка. Остальные флаги `git` продукт не перечисляет: их принимает
или отвергает `git` из `PATH`
([ADR-26101702][adr-git]).

### Запрещённые аргументы

Проверка один раз после резолва, до поиска копий. Нарушение — код `1`.

Правила токена и запрещённых ключей конфигурации — как у
[clone][clone-deny]. Дополнительно запрещён токен, если он равен
короткому флагу `-d`, `-c`, `-C`, `-f`, `-m` или `-t`, либо равен
длинному имени или начинается с `имя=` для `--detach`, `--orphan`,
`--guess`, `--no-guess`, `--create`, `--force-create`,
`--discard-changes`, `--merge` или `--track`. Токен с префиксом
`--force` запрещён тоже (`--force`, `--force-with-lease`).

## Итог

На каждую обработанную копию первая строка такая:

```text
<switch> <upstream> <путь>
```

Между знаками и перед путём один пробел. Как собирается путь —
[итог merge][merge-result].

Пояснения идут следом, каждое со сдвигом в четыре пробела. Сначала
переключение, потом вышестоящая ветка. У знаков `✔️` и `➡️` пояснения
нет. У `❌` и `⏩` следующая строка — краткий текст этого шага, без
повторения знака. У `⚔️` следующая строка снова начинается с `⚔️` и
перечисляет неслитые файлы так же, как в [итоге sync][sync-result].

| Знак | Когда |
| ---- | ----- |
| `✔️` | Переключение сменило ветку, сдвинуло коммит или при `--discard-changes` сбросило дерево. Вышестоящая ветка записана. |
| `➡️` | Переключение уже было на `<branch>`, коммит и дерево не менялись. Вышестоящая ветка не запрошена либо уже равна `<remote>/<branch>`. |
| `⚔️` | Только переключение: `--merge` оставил конфликт в копии. |
| `❌` | Шаг начался и не выполнен, либо чтение состояния для этого шага не удалось. |
| `⏩` | Вышестоящая ветка не настраивалась, потому что переключение не дало `✔️` или `➡️`. |

Пример. `architecture` перешла на `<branch>`, `--track` не задан.
`glossary` уже стояла на `<branch>`, вышестоящая ветка записана.
`specifications` остановилась на конфликте. `product-intent` не
переключилась. У `adr` переключение прошло, записать вышестоящую ветку
не удалось.

```text
✔️ ➡️ documentation/architecture
➡️ ✔️ documentation/glossary
⚔️ ⏩ documentation/specifications
    ⚔️ foo.md, bar.go
❌ ⏩ documentation/product-intent
    переключение не удалось
    не начинался
✔️ ❌ documentation/adr
    вышестоящая ветка не записана
```

## Коды выхода

| Код | Когда |
| --- | ----- |
| `0` | Проверка пройдена; пустой набор; отказ от [порога][mass-confirm]; интерактивный отбор отменён резолвером; не было знаков `❌` и `⚔️`. `✔️`, `➡️` и `⏩` код не портят. |
| `1` | Ошибка проверки параметров; [запрещённые аргументы][git-deny]; ошибка функции отбора или нет терминала при `--interactive` — по [резолверу][resolver]; нет терминала при [пороге][mass-confirm] без `--all`; `abort` на ошибке копии; `continue`, но в итоге был знак `❌` или `⚔️`. |
| `2` | Неверный вызов CLI (Cobra), если применимо. |

## Инварианты

- На каждую копию прогона приходятся одни и те же `<branch>`,
  `[start-point]`, флаги и список `--git-opts`.
- Локальная ветка создаётся только при `--create` или `--force-create`.
  `--no-guess` на `git switch` это удерживает.
- Конфликт `--merge` остаётся в копии. Команда его не снимает.
- Вышестоящая ветка меняется только при `--track` и только после
  переключения со знаком `✔️` или `➡️`.
- Повторов нет. `--retries-number` на ошибки копий не тратится.
