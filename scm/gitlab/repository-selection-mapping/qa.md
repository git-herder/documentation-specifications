# Маппинг `qa` (GitLab)

CLI → HTTP. Смысл `--qa` и разбор argv — [hub § qa][scm-repository-selection-qa].
Отбор на клиенте (все операторы, кроме `=`) —
[enumeration/qa.md](../repository-enumeration/qa.md).

## Когда включать

После резолва argv и профиля задан хотя бы один `--qa`. Иначе шаги ниже не
выполняем; в карточке `properties` = `{}`, как после base list в
[base-enumeration § карточка](../base-enumeration.md#карточка-репозитория).

## List проектов

Базовый запрос — `GET /api/v4/projects` ([base-enumeration](../base-enumeration.md)).
На каждую страницу добавляем [scope](scope.md) и [include-inactive](include-inactive.md).

| Условия `--qa` после резолва | Query |
| -------------------------- | ----- |
| Нет ни одного с оператором `=` (разбор — hub) | Параметры `custom_attributes[…]` не добавляем |
| Есть `=` (одно или несколько) | На каждое равенство: `custom_attributes[<key>]=<value>` |

Если в отборе есть условия «атрибут **равен** значению» (разбор флагов — hub):

1. Берёт из каждого такого `--qa` имя атрибута и значение.
2. На **каждый** запрос очередной страницы списка проектов добавляет к уже
   заданным параметрам (`scope`, `include-inactive` и т.д.) пары «имя атрибута →
   значение» в виде `custom_attributes[имя]=значение`. Спецсимволы в имени и
   значении кодирует так, как требует HTTP для строки запроса.
3. Несколько равенств задаёт **в одном** запросе страницы: все пары через `&`.
   Пример двух условий: `--qa foo=bar --qa bar=buzz` → в URL одновременно
   `custom_attributes[foo]=bar` и `custom_attributes[bar]=buzz`. GitLab должен
   вернуть только проекты, у которых **одновременно** выполняются все эти
   равенства (логика «и» на стороне сервера).

Условия с `!=`, `<`, `>`, `<=`, `>=` на этом шаге **не** использует: список
проектов запрашивает без них; отбор по ним будет позже, на уже собранных
карточках ([enumeration/qa.md](../repository-enumeration/qa.md)).

По документации GitLab такой отбор в list часто доступен только **администратору**
инстанса. Git Herder роль токена заранее не проверяет: если пользователь задал
равенства в `--qa`, параметры в запрос list **всё равно** добавляет; при отказе
(например 403) — см. раздел «Ошибки list» ниже.

## Дозагрузка `properties`

Сработает, если после резолва был хотя бы один `--qa`.

В цикле list проектов: после **каждой** полученной страницы (`GET /api/v4/projects`),
**до** запроса следующей страницы, для **каждого** репозитория на этой странице
выполнить шаги 1–5 ниже.

1. Отправляет запрос `GET /api/v4/projects/:id/custom_attributes`, подставив в
   `:id` числовой `uid` из карточки этого проекта.
2. Получает JSON-массив записей; у каждой записи в API есть строковые поля
   `key` (имя атрибута) и `value` (значение как текст).
3. Разбирает массив с первого элемента к последнему и собирает объект
   «имя → значение» для карточки. Если одно и то же имя встретилось несколько
   раз, оставляет значение из последней записи с этим именем.
4. Для каждой пары «имя → текст из API» определяет тип в карточке в таком
   порядке (как только правило сработало — дальше не смотрит):
   - если текст без учёта регистра равен `true` или `false` — записывает
     boolean;
   - иначе, если текст читается как число JSON (без экспоненты; целые без
     `.0`) — записывает number;
   - иначе, если текст приведёт к профилю data-timestamp
     ([ADR-26101704][adr-timestamp]) — записывает date (строка в JSON
     карточки);
   - иначе — записывает string (UTF-8 как в ответе API).
5. Заменяет поле `properties` в карточке этим объектом целиком (то, что
   было после base list — `{}` — не сохраняет).

Если API вернул пустой массив, кладёт в карточку `properties` = `{}`.
Как потом сравнивать значения при `--qa` — только
[карточка § qa][scm-repository-card-qa];

## Ошибки list (в том числе query `custom_attributes`)

Повторы — [`--retries-number`][cli-retries], дальше:

| Ситуация | Действие |
| -------- | -------- |
| **403** после всех повторов | Стоп команды; в сообщении — про custom attributes и права на list |
| Любая другая ошибка list после повторов | `abort` ([`--on-error`][cli-on-error]) — стоп; `continue` — пустой набор репозиториев, enrich не делаем |

Повторы — [cli/index.md][cli-retries].

## Ошибки `GET …/custom_attributes`

Повторы — [`--retries-number`][cli-retries], затем [`--on-error`][cli-on-error]:

| `--on-error` | Действие |
| ------------ | -------- |
| `abort` | Стоп команды |
| `continue` | У этого проекта `properties` не трогаем (остаётся `{}`); идём дальше |

## Порядок

1. List постранично: `scope`, `include-inactive`, при необходимости `custom_attributes[…]` для `=`.
2. На **каждой** странице list — enrich custom attributes (раздел выше), если после резолва был `qa`.
3. После всех страниц list — фильтры на клиенте — [enumeration/](../repository-enumeration/index.md).

## Не здесь

- Разбор argv, операторы, AND — hub.
- Проверка условий на карточке — [enumeration/qa.md](../repository-enumeration/qa.md).
