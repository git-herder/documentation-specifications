# Глобальные параметры CLI

Контракт **общеплатформенных** флагов `githerd`, наследуемых всеми подкомандами
дерева CLI.

Синонимы бинарника и продукта — в [замысле продукта][product-intent-readme].
Спеки отдельных команд ссылаются на этот документ и не повторяют таблицу
глобальных флагов.

## Назначение

Единые переключатели справки, версии, диагностики, политики ошибок и корня
локального workspace для любой команды, где они применимы. Команды, которым флаг
не нужен, явно указывают это в своей спеке.

## Синтаксис

```text
githerd [global options] <command> [command options] [arguments]
```

Глобальные опции — **persistent**: допустимы до и после имени подкоманды в
порядке, который принимает [Cobra][ADR-26101701] (длинные и короткие формы
эквивалентны).

## Глобальные опции

| Имя | Алиасы | Тип | Дефолт продукта | Описание |
| --- | ------ | --- | --------------- | -------- |
| `--version` | `-v` | flag | — | Вывести версию `githerd` и завершиться с кодом `0`. |
| `--help` | `-h` | flag | — | Вывести справку по текущему узлу дерева команд и завершиться с кодом `0`. |
| `--verbose` | `-V` | flag | `false` | Дублировать записи журнала выполнения на консоль (см. [Диагностические флаги](#диагностические-флаги)). |
| `--debug` | `-D` | flag | `false` | Включить расширенную диагностику в журнале (см. [Диагностические флаги](#диагностические-флаги)). |
| `--retries-number` | `-R`, `--retries` | целое ≥ 0 | `3` | Число **повторных** попыток после первой неудачи на объекте обработки; `0` — сразу [политика on-error](#повторы-и-политика-on-error). |
| `--on-error` | `-e` | `abort` \| `continue` | `continue` | Действие после исчерпания попыток (retry не является политикой). |
| `--workspace` | `-w`, `--dir` | путь | CWD | Каталог **корня workspace** с локальными рабочими копиями (см. [Workspace](#workspace)). |

### Короткие флаги

`-v` зарезервирован под **version**, не verbose; verbose — только `-V` /
`--verbose`. Это намеренное отличие от части POSIX-утилит.

## Версия (`--version`)

При `-v` / `--version` утилита пишет **одну строку** в stdout и не выполняет
подкоманду:

```text
githerd version <semver>
```

`<semver>` — версия сборки в формате [Semantic Versioning](https://semver.org/)
без префикса `v`. Идентификатор коммита и метка сборки в эту строку **не**
входят (их можно добавить в журнал или отдельную диагностику позже).

Код завершения: `0`.

## Справка (`--help`)

Поведение и текст справки формируются из регистрации команд в коде (Cobra).
Код завершения: `0`.

## Диагностические флаги

Журнал выполнения на один запуск, формат записи, путь во временной области ОС,
маскирование секретов и трассировка вызовов — SSOT в
[`platform/logging.md`](../platform/logging.md) (документ **planned**; см.
[SSOT map](../README.md)). Здесь — только контракт флагов.

### Базовая предпосылка

На каждый запуск утилиты ведётся журнал выполнения во временной области ОС
(замысел — [трассировка выполнения][operation-trace]). Глобальные
диагностические флаги **не отключают** этот журнал и **не создают** его: они
меняют детализацию и зеркалирование на консоль.

### `--verbose`

При `--verbose` / `-V` записи журнала **дополнительно** выводятся на консоль в
человекочитаемом виде. На консоль попадают **только** поля:

- уровень;
- метка времени;
- логгер;
- тред;
- текст сообщения.

Остальные поля записи остаются только в файле журнала (см. planned
`platform/logging.md`). Вывод для пользователя в терминале через pterm
([обратная связь в терминале][terminal-feedback]) **не заменяется** этим
зеркалом.

### `--debug`

При `--debug` / `-D` в журнал добавляются:

- вызовы функций с перечислением значений параметров;
- прочие диагностические записи уровня отладки.

Правила redaction, объём трассировки и формат строк — в planned
`platform/logging.md`.

### Совместное использование `-V` и `-D`

- `--debug` **без** `--verbose`: расширенная диагностика **только в файле**
  журнала; консольное зеркало **не** включается.
- `--verbose` **без** `--debug`: на консоль зеркалируются записи в объёме,
  принятом для обычного журнала (без debug-записей и без трассировки вызовов).
- Оба флага: в файл — полный debug-объём; на консоль — зеркало с тем же
  подмножеством полей, что и для `--verbose`, **включая** debug-записи, которые
  попали бы в журнал при `-D`.

## Повторы и политика `--on-error`

### Семантика `--retries-number`

Параметр **глобальный**: каждая команда в своей спеке описывает, что считается
одной **попыткой** (объект массовой обработки, сетевой шаг и т.д.), но имя флага
и дефолт едины для CLI.

Пусть `N` — значение `--retries-number`. При исключении в ходе обработки
репозитория или рабочей копии (в смысле команды):

1. выполняется до `N` **дополнительных** попыток после первой неудачи;
2. если после всех попыток объект всё ещё в ошибке — применяется `--on-error`.

`N = 0`: после **первого** исключения сразу шаг 2.

Retry — стандартное поведение до исчерпания попыток; `--on-error` — политика
**после** исчерпания.

```text
ошибка на объекте → повтор (до N раз) → всё ещё ошибка → on-error
```

Сетевые ретраи в массовых операциях согласуются с замыслом
[отказоустойчивого выполнения][resilient-network-execution]; трактовка «попытки»
для сетевого шага — в спеке соответствующей команды.

### Политика `--on-error`

| Значение | Поведение (платформа) |
| -------- | --------------------- |
| `abort` | Прервать **всю** команду при первом объекте, для которого попытки исчерпаны и ошибка сохраняется. |
| `continue` | Зафиксировать сбой объекта, **продолжить** обработку остальных объектов очереди команды. |

Отдельные команды могут расширять допустимые значения или уточнять смысл в своих
спеках; минимальный набор платформы — `abort` и `continue`.

Политика **не** применяется между попытками retry: только когда повторы для
объекта закончились.

## Workspace

`--workspace` задаёт каталог **корня workspace** для [локального отбора][repository-selection]
рабочих копий. Семантика «корень workspace» — как в capability отбора; отдельный
термин глоссария в этой итерации не вводится.

| Правило | Описание |
| ------- | -------- |
| Дефолт | Текущий рабочий каталог процесса (CWD) на момент разбора CLI. |
| Нормализация | Значение приводится к **абсолютному** пути ОС до начала выполнения команды. |
| Валидация | Для команд, использующих локальный отбор: путь должен **существовать** и быть **каталогом**; иначе ошибка до старта обработки объектов, ненулевой код завершения. |
| Неприменимость | Команды без локального отбора игнорируют флаг или отклоняют его — в спеке команды. |

## Приоритет конфигурации

Для глобальных опций из таблицы (кроме `--help` и `--version`):

```text
явные флаги CLI  >  профиль Git Herder  >  дефолт продукта
```

Ключи в YAML-профиле совпадают с длинными именами флагов **без** префиса `--`
(например `retries-number`, `on-error`, `workspace`). Переменные окружения и
полный порядок слияния — в planned `platform/config.md`.

## Коды завершения (общие)

| Код | Условие |
| --- | ------- |
| `0` | `--help` / `--version`; команда завершилась успешно; для массовых команд с `--on-error continue` — **все** объекты обработаны без ошибки после исчерпания попыток. |
| `1` | Ошибка выполнения: невалидные флаги, сбой валидации workspace, `--on-error abort` при ошибке объекта, `--on-error continue` при **хотя бы одном** неуспешном объекте после исчерпания попыток, иные фатальные сбои команды. |
| `2` | Некорректное использование CLI (неизвестная подкоманда, неверный синтаксис) — по соглашению Cobra; уточнение per-command допускается в спеках команд. |

Спеки команд могут вводить дополнительные коды; они не переопределяют коды для
`--help` и `--version`.

## Инварианты

- Глобальные флаги регистрируются один раз на корне CLI и наследуются
  подкомандами.
- `--on-error` не заменяет и не смешивается с retry.
- Диагностическое зеркало на консоль включается **только** флагом `--verbose`
  (или парой `-V` и `-D` для объёма debug на консоли — см. выше).
