# Очередь повторов

Контракт компонента **RetryingQueue**: как массовый прогон повторяет неуспешный
объект. Синтаксис `--retries-number` и `--on-error` —
[глобальные параметры CLI][cli-retries]. Здесь только поведение.

## Трассировка вверх

- [Отказоустойчивое выполнение массовых сетевых операций][resilient]
- [ADR-26110301][adr-retry] — решение о компоненте; поведение ниже ему следует
- Какой объект ставится в очередь при загрузке из SCM — [оркестрация][scm-index]

## Вход

| Вход | Смысл |
| ---- | ----- |
| Набор объектов | Очередь не интерпретирует, что это за объект |
| Обработчик | Функция «объект → ошибка»; успех — отсутствие ошибки |
| Число повторов | `--retries-number`: сколько раз повторить после первой ошибки. `0` — без повторов |
| Политика после исчерпания | `--on-error`: `abort` или `continue` |

## Выполнение

Пока очередь не пуста:

1. Извлечь объект.
2. Вызвать обработчик.
3. При ошибке, если повторы ещё есть, вернуть объект в конец очереди.
   Иначе применить политику:
   - `abort` — немедленно завершить прогон с признаком сбоя;
   - `continue` — зафиксировать неуспех объекта и перейти к следующему.

Прогон **последовательный**: следующего объекта нет, пока текущий вызов
обработчика не закончился.

Любая ошибка обработчика подлежит повтору. Очередь не делит ошибки на сетевые
и прочие. Отсев заведомо фатальных ошибок (неверные параметры, права) делается
**до** постановки объекта в очередь.

## Чего очередь не делает

- Не знает про SCM, HTTP и квоту запросов.
- Не ждёт сброса квоты. Удержание до момента сброса выполняет
  [HTTP-транспорт][transport] внутри обработчика. Для очереди это один долгий
  вызов, а не повтор.
- Если транспорт вернул ошибку, в том числе из-за квоты, очередь повторяет
  **весь объект**.
- Пауза между повторами и несколько исполнителей одновременно в этот контракт
  не входят.

## Объекты при загрузке из SCM

Состав объекта задаёт [оркестрация][scm-index]:

- перечисление — одна страница;
- обогащение — пара «карточка × задание». Обработчик пары — приём задания
  карточкой. Повтор снова полностью заменяет поля этого задания: как именно
  карточка передаёт порт записи, там же.

Прочие команды задают свой объект в своей спеке.

## Журнал `--debug`

При `--debug` на каждую ошибку объекта очередь пишет номер попытки, текст
ошибки и решение: `retry`, `continue` или `abort`. Итог прогона остаётся на
выходе очереди. Формат строки — [журнал][logging].
