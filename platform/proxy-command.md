# Прокси-команда

Общий контракт команд `pull`, `push`, `fetch` и `remote`. Каждая — это
[прокси-команда][PROXY-TERM]: отбирает рабочие копии и на каждой запускает
одноимённую команду git, передавая ей хвост аргументов без разбора.
Замысел — [массовые локальные git-операции][mass-ops].

Глагол git совпадает с именем команды и в хвост не входит. Подкоманда git,
например `add` у `remote`, в хвост входит и отдельной командой Git Herder
не становится.

## Синтаксис

```text
githerd [глобальные опции] <команда> [флаги префикса] [хвост]
```

`<команда>` — `pull`, `push`, `fetch` или `remote`. Глобальные флаги —
[глобальные параметры CLI][cli-index]. Команда не вызывает API SCM:
`upstream` и `token` не обязательны. Если они заданы, в процесс `git` не
передаются — [подключение к SCM][cli-scm].

## Префикс и хвост

Аргументы делятся на префикс и хвост, как в [определении][PROXY-TERM].
В префиксе только флаги Git Herder. Они могут стоять до имени команды и
сразу после него.

Флаги префикса:

- все [глобальные флаги][cli-index];
- `--qn` и `--qp` — повторяемые строки отбора;
- `--interactive` (`-i`) и `--all` (`-A`).

Токен принадлежит префиксу, только если это точное длинное имя, форма
`--имя=значение` или один короткий флаг из этого набора (`-w`, не `-wV`).
Склейка коротких флагов и короткое имя со значением в том же токене
префиксом не являются.

Значение флага, которому оно нужно, — следующий токен или часть после `=`.
Следующий токен не начинается с `-`. Иначе код `2`, поиск копий не
начинается. Значение, которое само начинается с `-`, записывают через `=`.
Синтаксис известных флагов — [синтаксис опций][cli-syntax].

Первый токен, который префиксом не является, начинает хвост. Хвост
копируется в git пословно и одинаков для каждой копии. Разделитель `--`
заканчивает префикс и в хвост не входит. `--` внутри уже начавшегося
хвоста копируется.

`-v`, `--verbose` и `--all` в префиксе — флаги Git Herder, не флаги git.
`-v` и `--version` печатают версию и завершают запуск с кодом `0` до
поиска копий. `--verbose` и `-V` — зеркало журнала. `--all` и `-A` —
пропуск [порога][mass-confirm]. Чтобы эти токены получил git, их ставят
после `--`.

```text
githerd remote -v
githerd remote -- -v
githerd fetch --all
githerd fetch -A -- --all
githerd pull --verbose
githerd pull -- --verbose
githerd pull -w ~/src --qn '^api-' --rebase origin main
githerd pull --rebase -- -h
```

Первая команда печатает версию. Вторая запускает `git remote -v`.
Третья пропускает порог и вызывает `git fetch` без `--all`. Четвёртая
вызывает `git fetch --all`. Пятая включает зеркало журнала и вызывает
`git pull`. Шестая вызывает `git pull --verbose`. Седьмая оставляет
`-w` и `--qn` в префиксе, хвост начинается с `--rebase`. Восьмая
передаёт git хвост `--rebase -- -h`: первый `--` в git не входит.

`-h` и `--help` в префиксе печатают справку команды и завершают запуск
с кодом `0` до поиска копий.

## Профиль

Из профиля в эту команду входят ключи `qn`, `qp`, `interactive`, `all`
и глобальные ключи по [правилам резолва][resolve]. Хвост из профиля не
читается. Повторы `--qn` и `--qp`: если флаг задан в командной строке,
берётся только она — [резолв с профилем][repeat-resolve].

`--retries-number` входит в резолв как глобальный флаг и число запусков
git не меняет.

## Поток выполнения

1. Делит argv на префикс и хвост. Справка или версия в префиксе —
   код `0`, поиск не начинается.
2. Собирает настройки префикса с профилем.
3. Проверяет префикс. Флаг без значения — код `2`. Прочие ошибки
   настроек — код `1` по [кодам выхода CLI][cli-exit], в том числе
   `--all` вместе с `--interactive` по [порогу][mass-confirm]. Поиск
   не начинается.
4. Ищет рабочие копии в `--workspace` через
   [поиск рабочих копий][resolver] и передаёт ему `--qn`, `--qp` и
   `--interactive`. Функции отбора нет.
5. Если копий нет — код `0`.
6. Сверяет число копий с [порогом подтверждения][mass-confirm].
   Отказ — код `0`.
7. Обрабатывает копии по одной, в порядке резолвера. На копию — чтение
   ремотов для токена, затем один пользовательский `git`. Пока копия
   не закончена, итог по ней не печатают. При `abort` итог неуспешной
   копии печатается, следующие копии не обрабатываются.

## Токен https

`--git-https-token` — глобальный флаг. Пустое значение не подставляется.
Непустое значение на этот запуск подставляется в URL каждого ремота
копии. Сохранённый URL в копии не меняется. `--token` в процесс `git`
не передаётся.

Пока токен непуст, до пользовательского `git` на этой копии:

1. `git remote` без аргументов. Каталог процесса — копия. Строки хода
   нет: вызов короткий — [ход шага][git-step].
2. Код не `0` или сбой запуска — знак `❌`, пользовательский `git` не
   запускается. Текст — по [итогу](#итог).
3. Код `0` и пустой stdout — пар `-c` нет.
4. Иначе каждая непустая строка stdout — имя [ремота][REMOTE-TERM].
   Для каждого имени выполняются `git remote get-url <имя>` и
   `git remote get-url --push <имя>`. Код не `0` или сбой запуска —
   как шаг 2.
5. На каждый непустой URL, одна и та же строка один раз, в аргументы
   процесса до глагола добавляется

```text
-c url.<https с userinfo>.insteadOf=<точный сохранённый URL>
```

Какой https берётся для схем `https` и `ssh` и какой пользователь
попадает в userinfo — как у [sync][sync] и у [флага][git-https].
Порядок пар — порядок имён в stdout `git remote`.

Пользовательский процесс:

```text
git <пары -c> <глагол> <хвост>
```

Каталог процесса — копия. Пустой хвост в команду ничего не добавляет.
Свой `--` продукт не вставляет.

На время пользовательского `git` видна [строка хода][git-step]. Слово
шага — глагол: `pull`, `push`, `fetch` или `remote`. Метка — путь из
[итога](#итог). Слова `attempt` нет: повторного запуска нет.
Stdout и stderr процесса на консоль не попадают: текст пишется в
[журнал прогона][logging].

## Итог

На каждую обработанную копию одна строка на stdout:

```text
<знак> <путь>
```

Между знаком и путём один пробел. Путь — как в
[итоге merge][merge-result]: относительно абсолютного `--workspace`.

| Знак | Когда |
| ---- | ----- |
| `✔️` | Пользовательский `git` завершился с кодом `0`. |
| `❌` | Чтение ремотов не выполнено или пользовательский `git` завершился с ненулевым кодом. |

У `✔️` второй строки нет. У `❌` следующая строка сдвинута на четыре
пробела: первая непустая строка stderr этого запуска, иначе первая
непустая строка его stdout, иначе `git failed`. Знак во второй строке
не повторяется.

## Коды выхода

| Код | Когда |
| --- | ----- |
| `0` | Справка или версия в префиксе; проверка пройдена и копий нет; отказ от порога; интерактивный отбор отменён резолвером; не было знака `❌`. |
| `1` | Ошибка настроек префикса; ошибка поиска или нет терминала при `--interactive` — по резолверу; нет терминала при пороге без `--all`; `abort` на ошибке копии; `continue`, но был знак `❌`. |
| `2` | Флаг префикса без значения; иной неверный вызов CLI. |

## Инварианты

- На каждую копию один и тот же глагол и один и тот же хвост.
- Очереди повторов нет.
- Продукт не разбирает хвост и не выбирает по нему ремот.
