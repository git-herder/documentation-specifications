# Структурированное логирование

Единый механизм журнала выполнения на один запуск процесса: **NDJSON** в файл во
временном каталоге ОС; при `-V` / `--verbose` те же события дополнительно в **TSV** на
**stderr**. Глобальные флаги и их смысл для пользователя —
[глобальные параметры CLI](../cli/index.md) (секция диагностических флагов).

Связь с замыслом: [трассировка выполнения](../../product-intent/capability/platform/operation-trace.md), [обратная связь в
терминале](../../product-intent/capability/platform/terminal-feedback.md), [профили](../../product-intent/capability/platform/profiles.md). Стек: [ADR-26101701](../../../ADR/ADR-26101701-go-application-stack.md)
(`log/slog`). Профили меток времени в имени и в полях: [ADR-26101704](../../../ADR/ADR-26101704-timestamp-formats.md).

Журнал **не** подменяет вывод пользователю через pterm. **stdout** для журнала не
используется.

## Управление из CLI

`-V` / `--verbose` — **только из CLI**; ключ `verbose` в YAML профиля игнорируется.
`-D` / `--debug` — CLI и [профиль YAML](profiles.md) по правилам резолва в
[profiles.md](profiles.md). Переменные окружения уровень логирования **не** задают.

### `--debug` (`-D`)

| Состояние флага | Что пишется в журнал |
| --------------- | -------------------- |
| отсутствует (по умолчанию) | **info** + **error** + **warn** + ключевые действия, принятые решения, значения-основания, сообщения об ошибках **включая** stack trace |
| присутствует | всё из режима по умолчанию + **debug** (вход и выход на [архитектурных границах](#debug); при ошибках дополнительно запись **error** со stack trace, см. ниже) |

Без `--debug` записей с `level=debug` **не создаётся**. Записи с `level=warn`
**создаются** (предупреждения видны в обычном режиме).

### `--verbose` (`-V`)

| Значение | Куда пишется |
| -------- | ------------ |
| `false` (по умолчанию) | только файл |
| `true` | файл **и** stderr (один и тот же набор событий; на stderr формат **TSV**, не JSON) |

Комбинации `-V` и `-D` — в [cli/index.md](../cli/index.md).

## Файл журнала

| Свойство           | Значение                                                                                  |
| ------------------ | ----------------------------------------------------------------------------------------- |
| Каталог            | системный temporary directory (`$TMP` / `%TEMP%`)                                         |
| Имя                | `git-herder-${timestamp}.log`                                                             |
| `${timestamp}`     | профиль **fs-timestamp** ([ADR-26101704](../../../ADR/ADR-26101704-timestamp-formats.md)) |
| Коллизия имён      | суффикс `-2`, `-3`, … перед `.log` в ту же миллисекунду (правила ADR)                     |
| Формат содержимого | **NDJSON**: одна строка UTF-8 = один JSON-объект + символ перевода строки. Символы `&`, `<`, `>` пишутся как есть, не как `\u0026`, `\u003c`, `\u003e`. |
| Создание           | при инициализации логгера (старт команды)                                                 |
| Закрытие           | при завершении процесса                                                                   |
| Путь пользователю  | **не сообщается**                                                                         |

## Поля JSON-записи

Каждая строка файла — один объект со следующими полями.

| Поле         | Обязательность               | Описание                                                                                                                                                          |
| ------------ | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `timestamp`  | всегда                       | локальное время хоста с offset; точность runtime не ниже миллисекунд; профиль **data-timestamp** ([ADR-26101704](../../../ADR/ADR-26101704-timestamp-formats.md)) |
| `level`      | всегда                       | `info`, `warn`, `error` или `debug` (lowercase)                                                                                                                   |
| `loggerName` | всегда                       | имя логгера в dot-notation (`cli.run`, …)                                                                                                                         |
| `threadId`   | при многопоточности          | идентификатор потока в рамках одного прогона; в однопоточном режиме ключ **отсутствует**                                                                          |
| `message`    | всегда                       | текст события                                                                                                                                                     |
| `stackTrace` | при ошибке на уровне `error` | stack trace исключения; в записях `info`, `warn`, `debug` ключ **отсутствует**                                                                                    |

Поле `stackTrace` заполняют только на записи с `level=error`, созданной для
исключения или ошибки с трассировкой стека.

## Семантика уровней

### WARN

Диагностические предупреждения, не прерывающие прогон. Пишутся **без** `--debug`.

### INFO

Обязательно логировать на уровне info:

- при старте команды: какой [профиль](../../product-intent/capability/platform/profiles.md) используется (имя или явное указание
на профиль по умолчанию);
- при старте команды: полная командная строка со всеми параметрами (после
[маскировки секретов](#маскировка-секретов));
- старт и завершение команды и шагов;
- принятые решения с **значениями**, на которых основано решение (в `message` в виде
пар `ключ=значение`, например `reason=…`, `path=…`, `count=…`);
- ошибки: человекочитаемое сообщение **без** stack trace.

При ошибке **без** `--debug` создаётся **одна** запись `level=info` с сообщением об
ошибке, без `stackTrace`.

### DEBUG

Только при `--debug`. Дополнительно к INFO — на **точке входа**, а не на каждом
внутреннем вызове внутри пакета.

**Точка входа** — экспортируемая операция пакета и обработчик команды. Сюда же
входит публичный метод контракта к внешней зависимости (git, HTTP, ФС, профиль).
Вспомогательная функция внутри пакета точкой входа не является.

Не пишутся вход и выход для:

- пути записи самого журнала (сборка строки, маскировка, метка времени);
- методов `Error`, `String`, `MarshalJSON` и геттеров;
- цепочек установки полей билдера и правки одной карточки;
- вывода в терминал.

`loggerName` — имя пакета в dot-notation (`scm.http`, `cli.report`,
`retrying`). Параметры и результат живут в `message`; отдельных полей JSON для
них нет. Значения проходят [маскировку](#маскировка-секретов).

На каждой точке входа две записи `level=debug`:

- **вход**: `enter`, имя единицы и пары `ключ=значение`;
- **выход**: `exit`, то же имя и пары результата. Нет возвращаемого значения —
  факт завершения без пар результата. Ошибка результата — пара `err`.

```text
enter Transport.Get baseURL=https://api.github.com path=search/repositories query=q=org%3Aacme
exit Transport.Get status=200 bodyLen=842 err=<nil>
```

Сериализация одного значения:

- строка или тело длиннее 2048 байт обрезается, хвост заменяется суффиксом
  `…(N bytes)`, где N — исходная длина в байтах;
- срез карточек — число элементов и `fullName`, без свойств;
- `context.Context` и функция — только факт (`ctx`, `fn`);
- пара, чьё имя совпадает с секретом из раздела маскировки (`token`,
  `password`, `authorization`, `private_token` и тот же набор), всегда `***`.

Исключение — debug-запись ответа SCM (заголовки и тело HTTP-ответа). В файл
она пишется целиком, предел 2048 байт к ней не применяется. На stderr та же
запись в колонке `message` обрезается до 2048 байт с тем же суффиксом.

События сверх входа и выхода названы в спеках компонентов. Формат строки,
предел длины и маскировка — в этом документе:
[HTTP-транспорт][scm-http-transport.md],
[очередь повторов][retrying-queue.md],
[SCM-отбор][scm-repository-selection.md].

### ERROR

Сообщения этого уровня приравнены к INFO, то есть выводятся всегда, вне зависимости от `--debug`.

## Зеркало на stderr (TSV)

При `-V` / `--verbose` каждое событие, попавшее в файл, дублируется одной строкой TSV
на **stderr**.

| Правило | Значение |
| ------- | -------- |
| Кодировка | UTF-8 |
| Разделитель колонок | символ табуляции (U+0009) |
| Заголовок колонок | **не** печатается |
| Порядок колонок | `timestamp`, `level`, `loggerName`, `threadId`, `message` |
| `level` | lowercase: `info`, `warn`, `error`, `debug` |
| `threadId` | пустое поле, если прогон однопоточный |

В колонке `message` символы табуляции и перевода строки кодируют escape-последовательностями
`\t` и `\n` (как в JSON-строке). Сырые U+0009 и U+000A внутри поля **не** допускаются.
Если `message` длиннее 2048 байт, на stderr остаётся префикс и суффикс
`…(N bytes)`; в файле строка не укорачивается.

Остальные поля JSON (в том числе `stackTrace`) на stderr **не** выводятся.

## Маскировка секретов

Перед записью в журнал (любой уровень, в том числе при `--debug`) чувствительные
значения заменяют на литерал `***`.

Маскируют как минимум:

- токены, PAT, пароли, приватные ключи;
- значения флагов и параметров, явно несущих секрет (включая аналоги `--token`);
- заголовки и фрагменты вроде `Authorization=…`;
- секреты из активного профиля и из переменных окружения, подставленные в командную
строку или в debug-параметры;
- чувствительные query-параметры в URL (например `token`, `password`, `private_token`).

Область применения: `message`, сериализованные параметры на входе/выходе debug,
командная строка в INFO. Режим `--debug` маскировку **не** отключает.

Детали хранения секретов в профиле — [platform/profiles.md](profiles.md); здесь только
правила журнала.

## Инварианты

- На каждый запуск процесса создаётся один файл журнала в temp.
- Файл всегда получает NDJSON; stderr используется только при `-V`.
- Набор событий в файле и в TSV при `-V` совпадает. Длинный `message` на
  stderr короче, чем в файле: см. [зеркало](#зеркало-на-stderr-tsv).
- `level=debug` только при включённом `debug` после резолва (CLI и/или профиль);
  `level=warn` всегда при наличии предупреждения.
- Debug-записи относятся к [границам](#debug), а не к каждой вспомогательной функции
  внутри реализации.
- Путь к файлу пользователю не сообщают.

## Не описывать здесь

- Реализацию в `application/`.
- Пошаговые сценарии отдельных команд (только ссылка на спеки команд).
- Полный контракт профиля (кроме отсылки к [profiles.md](profiles.md)).
