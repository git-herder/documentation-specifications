# publish

Команда `publish` публикует в текущей [SCM-платформе][SCM-PLATFORM-TERM]
рабочие копии из `--workspace`, которые ещё там не опубликованы. Для каждой
такой копии создаёт репозиторий, привязывает его к [ремоту][REMOTE-TERM] и
отправляет ветки.

## Контракт

### Синтаксис

```text
githerd [глобальные опции] publish <root> [опции publish]
```

Глобальные флаги — [глобальные параметры CLI][cli-index]. После сборки
настроек для `publish` нужны `upstream` и `token`; `host` — по
[подключению к SCM][cli-scm].

`<root>` — путь в SCM, префикс пути репозитория, сегменты через `/`.
Это позиционный аргумент, не флаг. Если аргумент задан, берётся он.
Иначе — ключ `root` блока `publish` в [профиле][profiles]. Нет ни
аргумента, ни ключа — код `1`, поиск копий не начинается.

`--workspace` / `-w` — каталог, в котором ищутся копии. Приведение к
абсолютному пути — [правила workspace][cli-workspace]. Команда этот флаг
не игнорирует.

### Опции команды

| Имя | Назначение |
| --- | ---------- |
| `--qn` | Повторяемая строка, по умолчанию не задана. Условие на имя копии. Сопоставление — [поиск рабочих копий][resolver]. |
| `--qp` | Повторяемая строка, по умолчанию не задана. Условие на путь копии. Сопоставление — [поиск рабочих копий][resolver]. |
| `--path-attribute` | Строка, по умолчанию не задана. Имя пользовательского атрибута организации GitHub. В него пишется относительный путь копии — [путь в атрибуте][attr-path]. |
| `--leaf-name` | Логический, по умолчанию выключен. На [плоской SCM][scm-flat] имя репозитория — только имя каталога копии. На [иерархической SCM][scm-hier] флаг задавать нельзя. |
| `--remote` | Имя, по умолчанию `origin`. Имя ремота, к которому привязывается созданный репозиторий. |
| `--existing` | `skip` или `rename`, по умолчанию `skip`. Что делать, если ремот `--remote` уже есть и указывает на другой URL — [привязка ремота][remote-bind]. |
| `--interactive` (`-i`) | Логический, по умолчанию выключен. Интерактивный отбор после программных фильтров. Передаётся [поиску рабочих копий][resolver]. |
| `--all` (`-A`) | Логический, по умолчанию выключен. Не спрашивать подтверждение, когда копий больше 10. |
| `--protocol` | `ssh` или `https`, по умолчанию `ssh`. Протокол URL ремота. Сборка адреса — как [адрес клонирования][clone-url]. |

В профиле YAML те же ключи без `--`: `qn`, `qp`,
`path-attribute`, `leaf-name`, `remote`, `existing`, `interactive`,
`all`, `protocol`. Ключ `root` — значение `<root>` ([профили][profiles]).
Логические флаги — по [синтаксису опций][cli-syntax].

Канон `--existing` — нижний регистр: `skip` или `rename`. Канон
`--protocol` — `ssh` или `https`.

## Поток выполнения

1. Собирает настройки из профиля и флагов. Порядок —
   [выбор значения][resolve].
2. Проверяет параметры и при ошибке завершается с кодом `1`, ничего не
   ища. Так бывает, если заданы сразу `--interactive` и `--all`; если
   нет `<root>` ни аргументом, ни ключом профиля; если разбор `<root>`
   по [пути в SCM][scm-path] негодный; если платформа
   [плоская][scm-flat] и сегментов `<root>` не ровно один; если
   платформа [иерархическая][scm-hier] и сегментов `<root>` не
   осталось; если задан `--leaf-name`, а платформа иерархическая; если
   `--existing` не `skip` и не `rename`; если `--protocol` не `ssh` и
   не `https`; если нет `upstream` или `token`. Если задан
   `--path-attribute`, к этому добавляется любое из условий: `upstream`
   не github, имя атрибута пустое.
3. Если задан `--path-attribute`, до поиска копий вызывает
   [предпроверку организации и свойства][github-preflight]. Организация
   — единственный сегмент `<root>`. Организация или свойство не найдены,
   либо тип свойства не `string`, — код `1`, поиск не начинается. Иная
   ошибка предпроверки после первой попытки повторяется ещё
   `--retries-number` раз, затем тоже код `1`. Без флага шаг не
   выполняется.
4. Ищет рабочие копии в `--workspace` через [поиск рабочих копий][resolver]
   и передаёт ему `--qn`, `--qp` и `--interactive`. Обход, фильтры по
   имени и пути, галочки и исходы интерактива заданы там. Функция отбора
   через GitCliRunner читает ремоты копии и оставляет её, только если
   ремотов нет или ни один их URL не содержит хост git текущего SCM.
   Хост git — хост подключения; у GitHub `api.github.com` читается как
   `github.com`. Копия, у которой ремот уже указывает на этот SCM, в
   новый запуск не входит. Досылка после сбоя отправки — только повтор
   того же объекта внутри текущей очереди.
5. Если после отбора копий нет, завершается с кодом `0`.
6. Если копий больше 10 и не заданы ни `--all`, ни `--interactive`,
   спрашивает, публиковать ли весь список. Отказ — код `0`. `--all`
   вопрос снимает. Десять копий и меньше подтверждения не требуют.
7. Если платформа [плоская][scm-flat], сравнивает имена репозиториев
   выбранных копий по [пути в SCM][scm-path]. Сравнение — строки
   Юникода точно, с учётом регистра. Одно и то же имя у разных копий —
   код `1`. Так бывает и при склейке: `a/b-c` и `a-b/c` дают `a-b-c`.
   Очередь не стартует, репозитории не создаются. На
   [иерархической SCM][scm-hier] шаг не выполняется.
8. Каждую оставшуюся копию ставит объектом в [очередь повторов][queue].
   Если задан `--path-attribute`, перед постановкой собирает
   [путь в атрибуте][attr-path]. Строка не годится — копия в очередь не
   ставится, итог `❌`, запрос записи не отправляется. Повтор строку не
   исправит. При `--on-error abort` на первой такой копии команда
   останавливается, остальные не обрабатываются. При `continue` обход
   продолжается. Повтор ошибки объекта и `--on-error` для очереди заданы
   в спеке очереди. На одну копию в очереди обработчик делает следующее:
   1. Собирает путь репозитория по [пути в SCM][scm-path].
   2. Проверяет, есть ли репозиторий по собранному пути. Если нет —
      создаёт его. Вызов идёт в клиент текущего `upstream`: его даёт
      **ScmRepositoryManagementFabric**, контракт вызова —
      **ScmRepositoryCreator**. Поток платформу не выбирает.
   3. Если задан `--path-attribute`, записывает уже собранную строку —
      [запись значения свойства][github-write]. Запись идёт до привязки
      ремота и не ждёт успешной отправки веток. При последующем `skip`
      значение уже записано. Повтор объекта записывает строку снова.
   4. Привязывает ремот — [привязка ремота][remote-bind].
   5. Отправляет ветки — [ветки][branches].
9. По каждой обработанной копии печатает строку [итога][result].
   Копия, отсеянная до очереди из-за строки атрибута, которая не
   годится, свою строку `❌` уже получила на шаге 8.

## Обработчик копии

Повтор ошибки обработчика и `--on-error` — [очередь повторов][queue].
Строка [итога][result] печатается, когда обработка копии закончилась.

### Привязка ремота

URL ремота собирается из страницы `https://{хост git}/{полный путь}` тем
же правилом `--protocol`, что [адрес клонирования][clone-url]. Хост git —
тот же, что при отборе копий в потоке выполнения.

Привязка выполняется через **GitCliRunner**.

Если ремот `--remote` уже указывает на этот URL, привязка не меняется.
Дальше выполняется отправка. Так повтор объекта внутри очереди не
переписывает ремот, созданный прошлой попыткой.

Если ремот `--remote` есть, но URL другой:

- `skip` — копия не меняется и не отправляется. Это не ошибка обработчика;
- `rename` — текущий ремот получает имя `{прежнее имя}_{секунды unix}`
  целым числом секунд. Затем создаётся ремот `--remote` с новым URL.

Если ремота `--remote` нет, он создаётся с этим URL.

### Ветки

Текущая ветка — та, на которую указывает `HEAD`. Отделённый `HEAD` —
ошибка объекта, отправки нет.

Дефолтная ветка — локальная `main`, если она есть, иначе `master`, если
она есть, иначе текущая.

Сначала `git push` дефолтной ветки в ремот `--remote`, затем текущей,
если она другая. Одна и та же ветка дважды не отправляется.

## Итог

На каждую обработанную копию печатается путь относительно абсолютного
`--workspace`. Корень `--workspace`, если он сам рабочая копия,
показывается как `.`.

| Знак | Когда |
| ---- | ----- |
| `✔️` | Отправлены дефолтная и текущая ветки. Если они совпали, достаточно одной отправки. |
| `❌` | Не отправлена ни одна ветка. Сюда же входит копия, у которой строка [пути в атрибуте][attr-path] не годится: она отсеяна до очереди. |
| `⚠️` | Репозиторий в SCM есть, одна ветка отправлена, вторая нет. |
| `➡️` | Сработал `skip`. Это не ошибка. |

## Путь в SCM

Имя каталога копии — последний сегмент пути копии по разделителю
каталогов системы. Пустые сегменты отбрасываются. Если копия — сам
корень `--workspace`, имя каталога — последний сегмент абсолютного
`--workspace`. Каталогов между `--workspace` и этим именем тогда нет.

Относительный путь — сегменты от абсолютного `--workspace` до копии
включительно, без самого `--workspace`. Пустые сегменты отбрасываются.
У копии-корня относительный путь пуст.

`<root>` делится по `/`. Пустые сегменты отбрасываются. Сегмент `.` или
`..` делает разбор негодным. Сегменты `<root>` в имя репозитория не
входят. Вид платформы — [топология SCM-платформы][scm-topo]. Какие
платформы плоские и какие иерархические, здесь не перечисляется.

Полный путь для URL — сегменты групп и имя репозитория через `/`.

### Иерархическая SCM

Сегменты групп — сегменты `<root>`, затем каталоги между абсолютным
`--workspace` и именем каталога копии. Имя репозитория — имя каталога
копии.

Для `upstream` gitlab недостающие группы и проект создаются по
[управлению репозиториями GitLab][gitlab-mgmt]. `path` карточки для
этого вызова — сегменты групп через `/`, `name` — имя репозитория.

### Плоская SCM

Сегментов групп ровно один — единственный сегмент `<root>`, владелец.

Имя репозитория:

- без `--leaf-name` — сегменты относительного пути, склеенные через
  `-`. Регистр сегментов и символы внутри сегмента не меняются.
  Относительный путь пуст — имя равно имени каталога копии. Пример:
  `work/org/team/api` даёт `work-org-team-api`, `work/org/other/api`
  даёт `work-org-other-api`;
- с `--leaf-name` — только имя каталога копии. Промежуточные каталоги
  в имя не входят.

Для `upstream` github проверка и создание — [управление репозиториями
GitHub][github-mgmt]. `path` карточки — сегмент владельца, `name` —
имя репозитория. Ошибка этого вызова — ошибка копии.

## Путь в атрибуте

Раздел действует, только если задан `--path-attribute`. Имя атрибута —
значение флага. Запись по HTTP — [запись значения свойства][github-write].

Строка — сегменты [относительного пути][scm-path] в том же порядке,
включая имя каталога копии, склеенные разделителем каталогов
операционной системы. Сегменты `<root>` в строку не входят.
Относительный путь пуст — строка из одной точки `.`.

Пример. `--workspace` равен `F:\work`, копия лежит в
`F:\work\domain\billing\api`, разделитель системы — `\`. Строка —
`domain\billing\api`.

Строка не годится, если она длиннее 75 символов, содержит `"` или
содержит символ с кодом вне диапазона 32–126. Такая копия не ставится
в очередь, запрос записи не отправляется.

## Коды выхода

| Код | Когда |
| --- | ----- |
| `0` | Проверка пройдена; пустой набор; отказ от подтверждения; интерактивный отбор отменён резолвером; не было строк `❌` и `⚠️`. `➡️` код не портит. |
| `1` | Ошибка проверки параметров или [предпроверки][github-preflight]; одинаковые имена репозиториев на [плоской SCM][scm-flat]; ошибка функции отбора или нет терминала при `--interactive` — по [резолверу][resolver]; `abort` на `❌` или `⚠️`; `continue`, но была хотя бы одна строка `❌` или `⚠️`. |
