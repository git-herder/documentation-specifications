# Глобальные параметры CLI

Общие флаги `githerd` для всего дерева команд. Подкоманды их наследуют.

Другие имена бинарника — в [замысле продукта][product-intent-readme]. В спеках
команд таблицу ниже не копируют, только ссылку на этот файл.

## Назначение

Один набор флагов для справки, версии, логов, обработки ошибок и каталога
workspace. Если команде флаг не нужен — это пишут в её спеке.

## Синтаксис

```text
githerd [глобальные опции] <команда> [опции команды] [аргументы]
```

Глобальные опции действуют на всех уровнях команд ([Cobra][ADR-26101701]).
Длинная и короткая форма равнозначны.

## Синтаксис опций

Разбор аргументов — [Cobra][ADR-26101701] и [pflag](https://github.com/spf13/pflag).
Длинные имена только с `--` (`--workspace`), короткие — с одним `-` (`-w`). Для
опции **со значением** допускаются обе записи: `--on-error continue` и
`--on-error=continue`; то же для короткой формы (`-e continue`, `-e=continue`).

**Флаги без значения** (boolean): включение — наличие опции (`-V`, `--verbose`);
явное выключение — `--verbose=false`. Форму `--verbose true` не используем потому,
что слово после boolean может уйти в позиционные аргументы.

**Разделитель `--`:** всё после `--` — не опции, а аргументы команды (пути и
имена, начинающиеся с `-`).

**Отрицательные числа и значения с `-`:** для целых и путей предпочитаем
`--retries-number=0` или аргументы после `--`; иначе `-1` может быть принят за
флаг.

Глобальные и локальные опции можно указывать до и после подкоманды, если иное
не сказано в спеке команды. Неизвестная опция — ошибка разбора (код выхода
`2`, см. [ниже](#коды-выхода)).

Опции с **несколькими значениями** (повтор флага, список через запятую) — в
спеке **конкретной** команды; общие правила не дублируем здесь.

## Таблица флагов

| Имя                | Алиасы            | Тип                   | По умолчанию | Что делает                                                                                        |
|--------------------|-------------------|-----------------------|--------------|---------------------------------------------------------------------------------------------------|
| `--version`        | `-v`              | флаг                  | —            | Печатает версию и выходит с кодом `0`.                                                            |
| `--help`           | `-h`              | флаг                  | —            | Печатает справку для текущей команды и выходит с кодом `0`.                                       |
| `--verbose`        | `-V`              | флаг                  | `false`      | Дублирует журнал на консоль — [ниже](#диагностические-флаги).                                     |
| `--debug`          | `-D`              | флаг                  | `false`      | Подробный журнал в файле — [ниже](#диагностические-флаги).                                        |
| `--retries-number` | `-R`, `--retries` | целое ≥ 0             | `3`          | Сколько раз **повторить** после первой ошибки; `0` — сразу [`--on-error`](#повторы-и---on-error). |
| `--on-error`       | `-e`              | `abort` \| `continue` | `continue`   | Что делать, когда повторы закончились.                                                            |
| `--workspace`      | `-w`, `--dir`     | путь                  | CWD          | [Корень workspace](#workspace) с рабочими копиями.                                                |

### Короткие флаги чувствительны к регистру

`-v` — только version, не verbose. Verbose — `-V` / `--verbose`. Так задумано
намеренно.

## `--version`

Одна строка в stdout, подкоманда не запускается:

```text
githerd version <semver>
```

`<semver>` — [Semantic Versioning](https://semver.org/) без буквы `v` в начале.
Коммит и метка сборки в строку не входят.

Код выхода: `0`.

## `--help`

Текст из кода (Cobra). Код выхода: `0`.

## Диагностические флаги

Файл журнала, NDJSON, TSV на stderr, маскировка секретов и поля записи — в
[`platform/logging.md`](../platform/logging.md) (см. [карту SSOT](../README.md)).
Здесь — только смысл флагов.

### Журнал на каждый запуск

При любом запуске пишется журнал во временный каталог ОС
([трассировка выполнения][operation-trace]). Флаги `-V` и `-D` журнал не
включают и не выключают: меняют детализацию и зеркало на stderr.

Флаги `--verbose` и `--debug` задаются **только из CLI**; профиль их не переопределяет.

### `--verbose`

С `-V` те же записи, что в файле журнала, **дополнительно** идут на **stderr** в формате
TSV (колонки и правила — [platform/logging.md](../platform/logging.md)). Сообщения
пользователю через pterm ([терминал][terminal-feedback]) это не заменяет.

### `--debug`

С `-D` в журнал попадают записи уровня debug (вход и выход процедур и функций) и при
ошибках запись error со stack trace; детали уровней — [platform/logging.md](../platform/logging.md).

### `-V` и `-D` вместе

| Флаги       | Файл журнала | stderr (`-V`)                          |
|-------------|--------------|----------------------------------------|
| только `-D` | подробно     | без дублирования                       |
| только `-V` | как обычно   | дублирование без debug                 |
| `-V` и `-D` | подробно     | дублирование, в том числе debug-записи |

## Повторы и `--on-error`

### `--retries-number`

Один флаг на весь CLI. Что считать одной попыткой (репозиторий, копия, сетевой
шаг) — в спеке **конкретной** команды.

`N` — значение флага. При ошибке на объекте:

1. до `N` повторов после первой ошибки;
2. если ошибка осталась — срабатывает `--on-error`.

При `N = 0` шаг 1 пропускается.

Повторы — до исчерпания лимита. `--on-error` — **после** лимита.

```text
ошибка → до N повторов → всё ещё ошибка → on-error
```

Сетевые повторы в массовых операциях — см.
[отказоустойчивое выполнение][resilient-network-execution]; детали — в спеке
команды.

### `--on-error`

| Значение   | Действие                                                          |
|------------|-------------------------------------------------------------------|
| `abort`    | Остановить всю команду на первом объекте, где повторы не помогли. |
| `continue` | Записать сбой, обработать остальные объекты.                      |

Команда может добавить свои значения в своей спеке. Минимум платформы: `abort`,
`continue`.

Между повторами `--on-error` не применяется.

## Workspace

`--workspace` — каталог корня workspace для [локального отбора][repository-selection].
Смысл «корень workspace» — как в capability отбора; отдельный термин в глоссарии
здесь не вводим.

| Правило      | Текст                                                                                                     |
|--------------|-----------------------------------------------------------------------------------------------------------|
| По умолчанию | CWD на момент разбора аргументов.                                                                         |
| Путь         | Приводится к абсолютному до старта команды.                                                               |
| Проверка     | Если команда использует локальный отбор: каталог должен существовать; иначе ошибка до обработки объектов. |
| Не нужен     | Команды без локального отбора: игнор или ошибка — в спеке команды.                                        |

## Откуда берётся значение

Для всех флагов из таблицы, кроме `--help` и `--version`:

```text
флаги в CLI  >  профиль  >  значение по умолчанию продукта
```

В YAML профиля ключи как у длинных имён без `--` (`retries-number`, `on-error`,
`workspace`). Переменные окружения — в `platform/config.md` (позже).

## Коды выхода

| Код | Когда                                                                                                                                 |
|-----|---------------------------------------------------------------------------------------------------------------------------------------|
| `0` | `--help`, `--version`; команда успешна; при `continue` — все объекты без ошибки после повторов.                                       |
| `1` | Ошибка: неверные флаги, плохой workspace, `abort` на сбое, `continue` но был хотя бы один сбой после повторов, другой фатальный сбой. |
| `2` | Неверный вызов CLI (нет команды, синтаксис) — по правилам Cobra; команда может уточнить в своей спеке.                                |

Дополнительные коды — только в спеках команд. Для `--help` и `--version` не
меняют.

## Инварианты

- Глобальные флаги задаются на корне CLI и наследуются.
- `--on-error` не подменяет повторы.
- Дублирование журнала на stderr — только с `-V` (при `-D` на stderr debug попадает
  только вместе с `-V`).
