# sync

Команда `sync` выравнивает текущую ветку рабочих копий из `--workspace`
с одноимённой веткой выбранного [ремота][REMOTE-TERM]. В прогон входят
только копии, которые уже стоят на `<branch-name>`. Замысел —
[двустороннее выравнивание рабочих копий][exchange].

## Контракт

### Синтаксис

```text
githerd [глобальные опции] sync <branch-name> [опции sync]
```

Глобальные флаги — [глобальные параметры CLI][cli-index]. Команда не
вызывает API SCM: `upstream` и `token` не обязательны. Если они заданы,
команда их не использует — [подключение к SCM][cli-scm].

`<branch-name>` — обязательный позиционный аргумент, не флаг: имя ветки.
Источники только два: аргумент, иначе ключ `branch` блока `sync` в
[профиле][profiles]. Общий блок профиля этот ключ не даёт. Нет ни
аргумента, ни ключа, либо имя пустое — код `1`, поиск копий не
начинается.

`--workspace` / `-w` — каталог, в котором ищутся копии. Приведение к
абсолютному пути — [правила workspace][cli-workspace]. Команда этот флаг
не игнорирует.

### Опции команды

| Имя | Назначение |
| --- | ---------- |
| `--qn` | Повторяемая строка, по умолчанию не задана. Условие на имя копии. Сопоставление — [поиск рабочих копий][resolver]. |
| `--qp` | Повторяемая строка, по умолчанию не задана. Условие на путь копии. Сопоставление — [поиск рабочих копий][resolver]. |
| `--remote` | Имя, по умолчанию `origin`. Ремот получения и отправки. Пустое имя после сборки настроек — код `1` до поиска. |
| `--interactive` (`-i`) | Логический, по умолчанию выключен. Интерактивный отбор после программных фильтров. Передаётся [поиску рабочих копий][resolver]. |
| `--all` (`-A`) | Логический, по умолчанию выключен. Не спрашивать [порог подтверждения][mass-confirm], когда копий больше 10. |

В профиле YAML те же ключи без `--`: `qn`, `qp`, `remote`,
`interactive`, `all`. Ключ `branch` — значение `<branch-name>`
([профили][profiles]). Логические флаги — по [синтаксису опций][cli-syntax].

`--git-https-token` — глобальный флаг, не опция `sync`. Непустое значение
при схеме `https` подставляется в URL этого запуска по
[правилу флага][git-https]. Сохранённый URL ремота в копии не меняется.
`--token` в процесс `git` не передаётся.

## Поток выполнения

1. Собирает настройки из профиля и флагов. Порядок —
   [выбор значения][resolve]. `<branch-name>` в этот порядок не входит.
2. Проверяет параметры и при ошибке завершается с кодом `1`, ничего не
   ища. Так бывает, если заданы сразу `--interactive` и `--all` — по
   [порогу подтверждения][mass-confirm]; если нет `<branch-name>` ни
   аргументом, ни ключом профиля; если имя ветки или имя `--remote`
   пустое.
3. Ищет рабочие копии в `--workspace` через
   [поиск рабочих копий][resolver] и передаёт ему `--qn`, `--qp` и
   `--interactive`. Функция отбора через **GitCliRunner** читает `HEAD`
   и оставляет копию, только если это локальная ветка
   `refs/heads/<branch-name>`. Сравнение имени точное. Отделённый `HEAD`
   и любая другая ветка отбрасываются, строка [итога][result] по ним не
   печатается. Нет символической ссылки `HEAD` на ветку — копия
   отбрасывается, это не ошибка функции. Сбой запуска `git` — ошибка
   функции, код `1` по [резолверу][resolver].
4. Если после отбора копий нет, завершается с кодом `0`.
5. Сверяет число копий, которые пойдут в очередь, с
   [порогом подтверждения][mass-confirm]. Отказ — код `0`.
6. Каждую оставшуюся копию ставит объектом в [очередь повторов][queue].
   Ошибкой обработчика считается только [сетевой сбой][net]. Расхождение,
   локальный отказ `git` и частичная отправка ошибкой обработчика не
   являются.
7. По каждой копии из очереди печатает строку [итога][result] один раз,
   когда очередь закончила объект. Пока есть следующая попытка, строку
   не пишут. При `abort` печатается строка неуспешного объекта, следующие
   копии не обрабатываются.

## Обработчик копии

Повтор ошибки обработчика и `--on-error` — [очередь повторов][queue].
Stdout и stderr процесса `git` на консоль не попадают: текст пишется в
[журнал прогона][logging].

Обмен идёт с `--remote` и `<branch-name>`, даже если локальная ветка
настроена на другой ремот. Ветка копии не переключается. История не
переписывается, принудительной отправки нет. Получение —
`git pull --no-rebase --ff <remote> <branch>`. Отправка —
`git push <remote> <branch>` без `--force`. Флаг `--ff` задаёт обычное
получение: перемотка, если она возможна, иначе слияние. Локальная
настройка «только перемотка» этот запуск в отказ не превращает.

Вызовы идут через **GitCliRunner**.

Незакоммиченные правки обработчик не снимает и не возвращает. Получение
идёт обычным `git pull` с тем деревом, которое уже есть в копии.

На одну попытку объекта обработчик делает следующее.

1. Если среди имён `git remote` нет `--remote`, знак `✖`. Получение и
   отправка не начинаются. Попытка на этом заканчивается.
2. Выполняется `git ls-remote --heads <remote> refs/heads/<branch>`.
   Из вывода берётся только строка, у которой имя ссылки точно
   `refs/heads/<branch>`. Идентификатор ремота — поле этой строки до
   табуляции. Другие строки не учитываются.
   - [Сетевой сбой][net] — отдать ошибку объекта.
   - Код `0` и такой строки нет — ветки на ремоте нет. Получение успешно
     и пустое: ничего не пришло, идентификатор `HEAD` не меняется. Дальше
     шаг 4, шаг 3 не выполняется.
   - Код `0` и строка есть — шаг 3.
   - Прочий ненулевой код — знак `✖`, отправки нет.
3. Только если на шаге 2 ветка на ремоте есть:
   `git pull --no-rebase --ff <remote> <branch>`. До запуска
   запоминается идентификатор `HEAD`.
   - Код `0` и слияния не осталось — получение успешно. Идентификатор
     `HEAD` отличается от запомненного — что-то пришло. Дальше шаг 4.
   - Незавершённое слияние проверяется раньше прочих ненулевых кодов:
     есть `MERGE_HEAD` или в индексе остались неслитые пути. Состояние
     слияния в копии сохраняется для ручного разрешения. Знак `⚔`,
     отправка не начинается. Пока это состояние есть, попытка не
     считается сетевым сбоем.
   - [Сетевой сбой][net] — отдать ошибку объекта.
   - Прочий ненулевой код — знак `✖`, отправки нет.
4. `git push <remote> <branch>`. Если на шаге 2 ветки не было, отправка
   её создаёт.
   - Код `0` — отправка успешна. Что пришло и что ушло — по
     [сравнению идентификаторов][oids].
   - [Сетевой сбой][net] — отдать ошибку объекта.
   - Прочий ненулевой код — знак `⚠`. Повтора нет.

### Сетевой сбой

Сетевой сбой — `git` не начал устойчивый обмен с ремотом: имя не
разрешилось, соединение не открылось или оборвалось, истекло ожидание,
транспорт отверг сессию до ответа об истории веток. Даже в этих случаях
сетевым сбоем не считаются отказ учётных данных, отсутствие ремота,
конфликт слияния, отказ отправки из-за истории, ошибка индекса. Класс
определяется по коду процесса и состоянию копии. Язык текста `git` на
класс не влияет.

### Сравнение идентификаторов

Идентификатор ремота запоминается на шаге `ls-remote`: поле до табуляции
в строке `refs/heads/<branch>`. Нет этой строки — идентификатор пуст.

Что-то пришло — после успешного получения идентификатор `HEAD` отличается
от запомненного до `git pull`. Пропущенное получение, когда ветки на
ремоте не было, идентификатор `HEAD` не меняет.

Что-то ушло — после успешной отправки идентификатор `HEAD` отличается от
идентификатора ремота. Пустой идентификатор ремота значит, что ветки не
было: успешная отправка её создала, поэтому отличие есть.

Оба шага успешны и ничего не пришло и не ушло — знак `➡️`. Оба шага
успешны и что-то пришло или ушло — знак `✔`. Текст сообщений `git` для
этого сравнения не читается.

## Итог

На каждую обработанную копию печатается одна строка. Сначала знак обмена,
затем пробел и путь относительно абсолютного `--workspace`.
Корень `--workspace`, если он сам рабочая копия, показывается как `.`.
Пример: `✔ api`. Второй строки нет.

Для `✖`, `⚠` и `⚔` после пути стоят двоеточие, пробел и первая непустая
строка ошибки попытки. Пустой текст — «получение не удалось» для `✖`
до сети, «обмен не удался» для `✖` после исчерпания сетевых повторов,
«отправка не удалась» для `⚠`, «слияние не завершено» для `⚔`.

| Знак | Когда |
| ---- | ----- |
| `✔` | Получение и отправка прошли, и что-то пришло или ушло. |
| `➡️` | Получение и отправка прошли, изменений не было. |
| `⚠` | Получение прошло, отправка нет. Это не ошибка обработчика. |
| `✖` | Получение не выполнено по несетевой причине, включая отсутствие ремота. Либо сетевой сбой после исчерпания повторов. |
| `⚔` | Слияние остановилось, состояние слияния в копии сохранено. Отправки не было. Это не ошибка обработчика. |

## Коды выхода

| Код | Когда |
| --- | ----- |
| `0` | Проверка пройдена; пустой набор; отказ от [порога][mass-confirm]; интерактивный отбор отменён резолвером; не было знаков `✖`, `⚠` и `⚔`. `➡️` код не портит. |
| `1` | Ошибка проверки параметров; ошибка функции отбора или нет терминала при `--interactive` — по [резолверу][resolver]; нет терминала при [пороге][mass-confirm] без `--all`; `abort` на сетевом сбое после повторов; `continue`, но была строка с `✖`, `⚠` или `⚔`. |
