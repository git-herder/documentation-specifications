# Управление репозиториями (GitHub)

Контракт компонента **GithubRepositoryManagement**: проверить владельца и
репозиторий на GitHub, создать репозиторий, проверить пользовательский
атрибут организации и прочитать или записать его значение у репозитория.
Запросы идут через [HTTP-транспорт][transport]. Повтора запроса здесь нет.

## Трассировка вверх

- [Публикация локальных рабочих копий в SCM][publish]
- [Массовое клонирование из SCM][mass-clone]
- [Обобщённая карточка репозитория][card] — поля `path` и `name`
- [ADR-26101703][adr-http] — обёртка над `net/http`

## Путь

Полный путь — `path` и `name` через `/`. `path` — ровно один сегмент, login
владельца. `name` — имя репозитория. Пустой `path`, пустой `name` или
`path` из нескольких сегментов — ошибка контракта до HTTP.

## Проверка репозитория

|              |                              |
| ------------ | ---------------------------- |
| Метод и путь | `GET /repos/{owner}/{repo}`  |
| `{owner}`    | единственный сегмент `path`  |
| `{repo}`     | `name`                       |

`200` — репозиторий для вызывающего есть. `404` — нет. Скрытый чужой
репозиторий платформа тоже отдаёт как `404`. Прочий код — ошибка вызова.

## Проверка владельца

Сначала `GET /orgs/{owner}`. `{owner}` — единственный сегмент `path`.

- `200` — владелец организация.
- `404` — затем `GET /users/{owner}`. `200` — владелец пользователь.
  `404` — владельца нет.
- Прочий код на любом из двух запросов — ошибка вызова. Второй запрос
  после такого кода не выполняется.

Организацию и пользователя компонент не создаёт.

## Создание репозитория

Тело запроса — объект с одним полем `name`, равным `name` карточки.
Видимость, описание и README компонент не передаёт.

Владелец-организация: `POST /orgs/{org}/repos`. `{org}` — сегмент `path`.

Владелец-пользователь: сначала `GET /user`. Поле `login` ответа должно
совпасть с сегментом `path`. Иначе ошибка до создания, `POST` не
отправляется. При совпадении — `POST /user/repos`.

Успех создания — `201`. Прочий код — ошибка вызова. Если проверка дала
`404` из-за скрытого репозитория, создание завершается ошибкой API.
Компонент не подменяет её успехом.

## Пользовательский атрибут

Имя организации, имя свойства, владелец и имя репозитория — непустые
строки. Организация и владелец — один сегмент, без `/`. Иначе ошибка
контракта до HTTP. Определение свойства компонент не создаёт.

### Предпроверка организации и свойства

Входы — имя организации и имя свойства.

1. `GET /orgs/{org}`. `{org}` — имя организации.
   - `200` — организация есть.
   - `404` — организации нет. `GET /users/{org}` не выполняется.
   - Прочий код — ошибка вызова. Второй запрос не выполняется.
2. `GET /orgs/{org}/properties/schema/{custom_property_name}`.
   `{custom_property_name}` — имя свойства.
   - `200` и `value_type` равен `string` — свойство годится.
   - `200` и другой `value_type` — ошибка вызова.
   - `404` — свойства нет.
   - Прочий код — ошибка вызова.

### Чтение значения свойства

Запрос тот же, что [дозагрузка `properties`][github-enrich-props]:
`GET /repos/{owner}/{repo}/properties/values`. `{owner}` — владелец,
`{repo}` — имя репозитория. Разбор полей карточки там не повторяется.

`200` — массив элементов с `property_name` и `value`. Берётся элемент с
именем свойства. При повторе имени берётся последний.

- Элемента нет или `value` равен `null` — значения нет. Это не ошибка
  вызова.
- `value` — строка. Это значение.
- `value` другого типа JSON — значение не строка. Это не ошибка вызова.

Прочий код, включая `404` репозитория, — ошибка вызова.

### Запись значения свойства

`PATCH /repos/{owner}/{repo}/properties/values`. `{owner}` — владелец,
`{repo}` — имя репозитория.

Тело — объект с полем `properties`: массив из одного объекта. У этого
объекта `property_name` — имя свойства, `value` — строка. Других свойств
репозитория тело не содержит, запрос их не меняет.

Успех — `204`. Прочий код — ошибка вызова.

## Не здесь

- Повтор неуспешного вызова. Транспорт ошибку не повторяет.
- Код выхода команды и политика «репозиторий уже есть».
- Как из каталога workspace собираются `path` и `name`.
- Изменение и удаление репозитория.
- Создание и удаление определения свойства в схеме организации.
