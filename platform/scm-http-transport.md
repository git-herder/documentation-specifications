# HTTP-транспорт SCM

Контракт компонента **ScmHttpTransport**: один вызов HTTP к SCM и квота
запросов платформы. Повтора запроса здесь нет — его делает
[очередь повторов][queue].

## Трассировка вверх

- [Отказоустойчивое выполнение][resilient] — удержание до сброса квоты не
  заменяет повтор неуспешного вызова
- [ADR-26101703][adr-http] — обёртка над `net/http`, без встроенного повтора
- Уже разрешённые базовый адрес и учётные данные — [подключение к SCM][cli-scm]
  и [профили][profiles]

## Экземпляр

Один экземпляр на `upstream` текущего запуска. Его совместно используют
перечисление и обогащение. Отдельный экземпляр на каждое задание разошёлся бы
в остатке: один уже видит нулевой остаток, другой ещё отправляет запрос.

При создании экземпляр получает:

| Вход | Смысл |
| ---- | ----- |
| Базовый адрес | Уже разрешённый адрес API (`host`) |
| Учётные данные | Уже разрешённый секрет доступа |
| Разбор квоты | Функция: полный ответ → предел, остаток, израсходовано, момент сброса |
| Политика при нулевом остатке | Ждать до момента сброса или отказаться от запроса |
| Оповещение перед удержанием | Функция, которую транспорт вызывает перед ожиданием |

Транспорт не читает профиль, флаги и переменные окружения. Секрет приходит
снаружи. Источник значения — `--token` и профиль
([профили][profiles]: настройки из окружения не читаются).

Платформа без квоты передаёт пустой разбор: значения не устанавливаются,
удержания нет. Сейчас так устроен GitLab.

## Вызов

На вход — запрос. На выход — код состояния и тело.

После любого ответа транспорт вызывает разбор квоты и передаёт ему ответ
целиком. Транспорт не разбирает заголовки конкретной платформы.

Пока разбор ни разу не установил квоту, остаток неизвестен и удержания нет.

Перед запросом, если остаток равен нулю:

- политика ожидания — вызвать оповещение и удерживать вызов до момента
  сброса, затем выполнить запрос;
- политика отказа — запрос не выполнять и вернуть ошибку исчерпания квоты.

Транспорт не пишет в консоль. Текст предупреждения задаёт оповещение.
Для GitHub политика, оповещение и код выхода — [options][github-options];
какие заголовки записывает разбор — [квота GitHub][github-quota].

Квота хранится внутри экземпляра:

| Значение | Смысл |
| -------- | ----- |
| Предел | Сколько запросов в текущем окне |
| Остаток | Сколько запросов ещё можно сделать |
| Израсходовано | Сколько запросов окна уже сделано |
| Момент сброса | Когда окно заканчивается |

## Журнал `--debug`

Помимо входа и выхода вызова ([журнал][logging]) транспорт пишет:

- до отправки: метод, URL, заголовки запроса, длину тела и тело;
- после ответа: код, заголовки ответа, длину тела, тело и ошибку транспорта;
- перед удержанием из-за нулевого остатка: остаток, момент сброса, политику
  (`await` или `abort`) и длительность ожидания.

Формат строки, предел длины и маскировка — [журнал][logging].

## Не здесь

- Повтор неуспешного вызова — [очередь][queue]. Ошибка транспорта, в том
  числе исчерпание квоты, для очереди обычная ошибка объекта.
- Соответствие заголовков GitHub четырём значениям и сдвиг момента сброса —
  [base-enumeration][github-quota].
- Флаг `--on-limit-exceeded` и текст предупреждения —
  [options GitHub][github-options].
