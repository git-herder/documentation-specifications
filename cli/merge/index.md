# merge

Команда `merge` сливает локальную ветку `<from>` в ветку `[to]` каждой
отобранной рабочей копии из `--workspace`. Перед слиянием обновляет
ссылки удалённого слежения выбранного
[ремота](../../../../glossary/terms/remote.md). Локальную
`<from>` это получение не двигает. Очереди повторов нет. Замысел —
[массовые локальные git-операции](../../../product-intent/capability/local/mass-local-git-operations.md).

## Контракт

### Синтаксис

```text
githerd [глобальные опции] merge <from> [to] [опции merge]
```

Глобальные флаги — [глобальные параметры CLI](../index.md). Команда не
вызывает API SCM: `upstream` и `token` не обязательны. Если они заданы,
команда их не использует — [подключение к SCM](../index.md#подключение-к-scm).

`<from>` — обязательный позиционный аргумент: имя локальной ветки.
`[to]` — необязательный позиционный аргумент: имя ветки, в которую
сливают. Оба значения команда читает из Invocation после резолва.
Ключи блока `merge` в профиле — `from` и `to`. Порядок выбора —
[выбор значения](../../platform/profiles.md#порядок-выбора-значения),
здесь он не пересказывается. Общий блок
профиля эти ключи не даёт.

Нет значения `<from>` или строка пустая — код `1`, поиск копий не
начинается. Нет значения `[to]` — имя берётся по
[правилу умолчания](#имя-to-по-умолчанию). Пустая строка `[to]` — код `1`, до
поиска. После этого `<from>` и `[to]` совпали — тоже код `1`, до поиска.

`--workspace` / `-w` — каталог, в котором ищутся копии. Приведение к
абсолютному пути — [правила workspace](../index.md#workspace). Команда этот флаг
не игнорирует.

### Опции команды

| Имя                           | Назначение                                                                                                                                                           |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--qn`                        | Повторяемая строка, по умолчанию не задана. Условие на имя копии. Сопоставление — [поиск рабочих копий](../../platform/git-working-copies-resolver.md).              |
| `--qp`                        | Повторяемая строка, по умолчанию не задана. Условие на путь копии. Сопоставление — [поиск рабочих копий](../../platform/git-working-copies-resolver.md).             |
| `--remote`                    | Имя, по умолчанию `origin`. [Ремот](../../../../glossary/terms/remote.md) для `git fetch`. Пустое имя после резолва — код `1` до поиска.                             |
| `--interactive` (`-i`)        | Логический, по умолчанию выключен. Интерактивный отбор после программных фильтров. Передаётся [поиску рабочих копий](../../platform/git-working-copies-resolver.md). |
| `--all` (`-A`)                | Логический, по умолчанию выключен. Не спрашивать [порог подтверждения](../../platform/mass-confirm.md), когда копий больше 10.                                       |
| `--stay` (`-s`)               | Логический, по умолчанию выключен. После успеха вернуться на ветку входа. См. [пост-обработку](#пост-обработка).                                                     |
| `--keep-source-branch` (`-k`) | Логический, по умолчанию выключен. После успеха не удалять локальную `<from>`. См. [пост-обработку](#пост-обработка).                                                |
| `--git-opts`                  | Повторяемая строка, по умолчанию не задана. Аргументы каждого вызова `git` в [обработчике](#обработчик-копии), по одному на повтор.                                  |
| `--git-fetch-opts`            | Повторяемая строка, по умолчанию не задана. Аргументы только `git fetch`.                                                                                            |
| `--git-switch-opts`           | Повторяемая строка, по умолчанию не задана. Аргументы только `git switch`.                                                                                           |
| `--git-merge-opts`            | Повторяемая строка, по умолчанию не задана. Аргументы только `git merge`.                                                                                            |
| `--git-branch-opts`           | Повторяемая строка, по умолчанию не задана. Аргументы только `git branch`.                                                                                           |

В профиле YAML те же ключи без `--`. Логические флаги — по
[синтаксису опций](../index.md#синтаксис-опций). Повтор в профиле — скаляр или
последовательность ([структура YAML](../../platform/profiles.md#структура-yaml)).

`--stay` и `--keep-source-branch` можно задать вместе.

`--git-https-token` — глобальный флаг, не опция `merge`. На процесс
`git fetch` непустое значение подставляется так же, как на `git pull` и
`git push` у [sync](../sync/index.md#опции-команды). На остальные
процессы `git` этой команды
флаг не влияет. `--token` в процесс `git` не передаётся.

## Поток выполнения

1. Берёт параметры из Invocation. Если `[to]` нет, подставляет

   [имя по умолчанию](#имя-to-по-умолчанию).
2. Проверяет параметры и при ошибке завершается с кодом `1`, ничего не

   ища. Так бывает, если заданы сразу `--interactive` и `--all` — по
      [порогу подтверждения](../../platform/mass-confirm.md);
      если нет `<from>`, имя ветки
      или имя `--remote` пустое; если `<from>` совпало с `[to]`; если в
      списках аргументов `git` есть
      [запрещённый аргумент](#запрещённые-аргументы); если
      не удалось запустить `git` для [имени по умолчанию](#имя-to-по-умолчанию).
3. Ищет рабочие копии в `--workspace` через

   [поиск рабочих копий](../../platform/git-working-copies-resolver.md)
   и передаёт ему `--qn`, `--qp` и
      `--interactive`. Функция отбора через **GitCliRunner** проверяет
      локальную ветку вызовом `git rev-parse --verify --quiet` с операндом
      `refs/heads/<from>`. Код `0` — копия остаётся. Код `1` — ветки нет,
      копия отбрасывается, строка [итога](#итог) по ней не печатается.
      Это не ошибка функции. Любой другой код и сбой запуска `git` —
      ошибка функции, код `1` по
      [резолверу](../../platform/git-working-copies-resolver.md).
      Отсутствие
      локальной `[to]` копию не отбрасывает. Аргументы `--git-opts` и
      списки подкоманд этому вызову не передаются.
4. Если после отбора копий нет, завершается с кодом `0`.
5. Сверяет число копий, которые пойдут в прогон, с

   [порогом подтверждения](../../platform/mass-confirm.md). Отказ — код `0`.
6. Обрабатывает оставшиеся копии по порядку обнаружения, без

   [очереди повторов](../../platform/retrying-queue.md).
   `--retries-number` команда не применяет.
      Ошибка копии сразу подчиняется `--on-error`: `abort` печатает
      [итог](#итог) этой копии и не обрабатывает следующие; `continue`
      переходит к следующей. Смысл значений — [флаг](../index.md#--on-error) `--on-error`,
      шага повторов перед ним нет.
7. По каждой обработанной копии печатает [итог](#итог) один раз, когда
   обработка копии закончилась.

## Имя to по умолчанию

Один вызов на прогон, без `-C` рабочей копии:

```text
git config --get init.defaultBranch
```

Сбой запуска `git` — код `1`, поиск не начинается. Код `0` и непустая
первая строка stdout — это имя `[to]`, без пробелов по краям. Ключа нет
или строка пустая — имя `master`. Имя общее для всех копий прогона.

## Обработчик копии

Stdout и stderr процесса `git` на консоль не попадают: текст пишется в
[журнал прогона](../../platform/logging.md). На время шагов `fetch` и `merge` видна
[строка хода](../../platform/git-step-status.md). Слово шага —
`fetch` или `merge`. Метка — путь
из [итога](#итог). Повторной попытки нет, поэтому `attempt` в строке
не появляется. `<сделано>` и `<всего>` считаются по копиям этого
прогона: отсеянные до него в счёт не входят.

Вызовы, которые только читают состояние, не получают `--git-opts` и
списки подкоманд. Это предпроверка, чтение ветки входа, сравнение
идентификаторов и список неслитых файлов.

На каждую копию обработчик сначала запоминает вход. Вызов
`git symbolic-ref --quiet HEAD` с кодом `0` даёт имя ветки: участок
после `refs/heads/`. Иначе `git rev-parse --verify HEAD` — отделённый
`HEAD`, запоминается идентификатор коммита. Оба вызова не дали
идентификатор — ошибка копии до получения, копия не меняется.

### Предпроверка

До `git fetch`. Любое срабатывание — ошибка копии, получение не
начинается, копия не меняется. Проверки по порядку, хватает первой.

1. Уже идёт операция. Код `0` у `git rev-parse --verify --quiet` для

   `MERGE_HEAD` — слияние. То же для `CHERRY_PICK_HEAD` — перенос
      коммита. Существующий каталог по `git rev-parse --git-path` для
      `rebase-merge` или `rebase-apply` — перебазирование.
2. Грязное дерево: `git status --porcelain=v1` печатает хотя бы одну

   строку. Учитываются и неотслеживаемые файлы.

Сбой запуска `git` на этих проверках — та же ошибка копии.

### Получение

```text
git fetch <аргументы --git-opts> <аргументы --git-fetch-opts> -- <remote>
```

Операнд продукта — только имя `--remote`. Локальная `<from>` не
меняется: продукт не передаёт refspec. Код `0` — шаг успешен. Ненулевой
код — ошибка копии, переключение не начинается.

### Переключение

```text
git switch <аргументы --git-opts> <аргументы --git-switch-opts> -- [to]
```

Продукт не ставит `--no-guess`. Если локальной `[to]` нет, но
одноимённая ветка есть ровно на одном ремоте, `git` может создать
локальную ветку сам. Нет такого совпадения — `git` завершается с
ошибкой. Отказ переключения — ошибка копии. `HEAD` не возвращают:
переключение его не сменило. Слияние не начинается.

Успех и символическая ветка после вызова совпала с запомненной веткой
входа — ветка не менялась. Иначе переключение сменило ветку. Вход был
отделённым — любое успешное переключение на `[to]` считается сменой.

### Слияние

```text
git merge --no-edit <аргументы --git-opts> <аргументы --git-merge-opts> -- <from>
```

`--no-edit` ставит продукт. Перемотку продукт не задаёт: её решают `git`
и аргументы вызова.

Исход смотрят так.

- [Незавершённое слияние](../sync/index.md#сетевой-сбой) — конфликт.
Состояние в копии
сохраняется, `HEAD` остаётся на `[to]`. Это ошибка копии.
[Пост-обработка](#пост-обработка) не выполняется: `<from>` не удаляется, возврат
на ветку входа не делается, в том числе при `--stay`.
- Код `0` — успех. Идентификатор `HEAD` сравнивают с запомненным сразу
после успешного переключения. Совпал — изменений не было, в том числе
«Already up to date». Не совпал — `[to]` сдвинулась. Дальше
[пост-обработка](#пост-обработка).
- Прочий ненулевой код, если слияния не осталось, — ошибка копии.
Удаление `<from>` не начинается. Если переключение сменило ветку,
обработчик возвращает вход тем же вызовом, что [возврат](#пост-обработка).
Если не сменило — `HEAD` не трогает.

### Пост-обработка

Выполняется только после успешного слияния.

Удаление — `git branch -d`. Оно запускается, только если
`--keep-source-branch` выключен и ветка, на которой копия останется, не
равна `<from>`. Без `--stay` копия остаётся на `[to]`. С `--stay` она
останется на ветке входа; если вход был отделённым `HEAD`, эта ветка не
равна `<from>`, и удаление разрешено. Оба флага вместе: возврат есть,
удаления нет. `--stay` и ветка входа равна `<from>`: удаления нет при
любом `--keep-source-branch`.

```text
git branch -d <аргументы --git-opts> <аргументы --git-branch-opts> -- <from>
```

Код `0` — ветка удалена. Ненулевой код — ошибка копии. Продукт не
повторяет удаление как `git branch -D`. Слияние на `[to]` сохраняется.
Дальше возврат всё равно выполняется, если задан `--stay`.

Возврат выполняется, если задан `--stay`. Ветка входа:

```text
git switch <аргументы --git-opts> <аргументы --git-switch-opts> -- <ветка входа>
```

Отделённый вход:

```text
git switch --detach <аргументы --git-opts> <аргументы --git-switch-opts> -- <идентификатор>
```

Текущая ветка уже равна ветке входа — вызов не делается. Ненулевой код —
ошибка копии. Возврат идёт на запомненное имя, не через `git switch -`.

Тот же возврат используется, когда слияние отказало без
[незавершённого слияния](../sync/index.md#сетевой-сбой), а переключение успело сменить
ветку. В этом случае `--stay` не требуется.

## Передача параметров git

Один и тот же список `--git-opts` уходит в каждый вызов `git` обработчика
копии. Список подкоманды добавляется только к своей подкоманде: и к
переключению на `[to]`, и к возврату. Чтение `init.defaultBranch` и
функция отбора эти списки не получают.

Каждое значение — один аргумент процесса, в порядке повторов флага или
элементов последовательности в профиле. Если флаг задан в командной
строке, берётся только она, список из профиля не подмешивается — то же
правило происхождения, что у повторяемых критериев
([резолв с профилем](../../platform/scm-repository-selection.md#резолв-с-профилем)).
Значение записывают через `=`,
потому что оно само начинается с `-`:

```text
githerd merge feature --git-merge-opts=--ff-only --git-fetch-opts=--prune
```

В профиле значение — скаляр или последовательность
([структура YAML](../../platform/profiles.md#структура-yaml)):

```yaml
merge:
  git-merge-opts:
    - --ff-only
  git-fetch-opts: --prune
```

Пустые списки в команде ничего не подставляют. Остальные флаги `git`
продукт не перечисляет: их принимает или отвергает `git` из `PATH`
([ADR-26101702](../../../../ADR/ADR-26101702-host-git-from-path.md)).

### Запрещённые аргументы

Проверка один раз после резолва, до поиска копий. Нарушение — код `1`.
Проверяется каждый из списков `--git-opts`, `--git-fetch-opts`,
`--git-switch-opts`, `--git-merge-opts`, `--git-branch-opts`.

Правила токена и запрещённых ключей конфигурации — как у
[clone](../clone/index.md#запрещённые-аргументы). Дополнительно запрещён токен `--abort`,
`--continue`, `--quit` или `--edit`, в том числе с `=<значение>` после
имени.

## Итог

На каждую обработанную копию первая строка такая:

```text
<fetch> <switch> <merge> <delete> <return> <путь>
```

Между знаками и перед путём один пробел. Путь — относительно абсолютного
`--workspace`, сегменты через `/`. Корень `--workspace`, если он сам
рабочая копия, показывается как `.`.

Пояснения идут следом, каждое со сдвигом в четыре пробела, в порядке
шагов: получение, переключение, слияние, удаление, возврат. У знаков
`✔️` и `➡️` пояснения нет. У `❌` и `⏩` следующая строка — краткий
текст этого шага, без повторения знака. У `⚔️` следующая строка снова
начинается с `⚔️` и перечисляет неслитые файлы так же, как в
[итоге sync](../sync/index.md#итог).

Текст `❌` — первая непустая строка stderr запуска `git` этого шага,
иначе первая непустая строка его stdout. Если обе пусты, своя фраза:
`fetch failed`, `switch failed`, `merge failed`, `branch delete failed`,
`return failed`. Свои тексты предпроверки, без запуска шага:
`merge already in progress`, `cherry-pick already in progress`,
`rebase already in progress`, `uncommitted changes`, `no commit at HEAD`,
`working copy check failed`. Текст предпроверки относится к получению,
знак этого шага — `⏩`. Шаг, до которого выполнение не дошло, — `⏩`
и текст `did not start`.

| Знак | Когда |
| ---- | ----- |
| `✔️` | Получение с кодом `0`. Переключение сменило ветку или создало её. Слияние сдвинуло `[to]`. Удаление удалило ветку. Возврат ушёл на вход. |
| `➡️` | Переключение уже было на `[to]`. Слияние ничего не изменило. Удаление не требовалось. `--stay` не задан, либо возврат не нужен, потому что ветка и так входная. |
| `⚔️` | Только слияние: конфликт оставлен в копии. |
| `❌` | Шаг начался и не выполнен. |
| `⏩` | Шаг не начинался. В том числе получение, остановленное предпроверкой. |

Пример без `--stay` и без `--keep-source-branch`. `architecture` прошла
все шаги и осталась на `[to]`. У `glossary` слияние ничего не изменило,
но `<from>` всё равно удалена. `specifications` остановилась на
конфликте. `product-intent` не прошла предпроверку.

```text
✔️ ✔️ ✔️ ✔️ ➡️ documentation/architecture
✔️ ➡️ ➡️ ✔️ ➡️ documentation/glossary
✔️ ✔️ ⚔️ ⏩ ⏩ documentation/specifications
    ⚔️ foo.md, bar.go
⏩ ⏩ ⏩ ⏩ ⏩ documentation/product-intent
    uncommitted changes
```

## Коды выхода

| Код | Когда                                                                                                                                                                                                                                                                                                                                                                                     |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------                                  |
| `0` | Проверка пройдена; пустой набор; отказ от [порога](../../platform/mass-confirm.md); интерактивный отбор отменён резолвером; не было знаков `❌` и `⚔️` и ни одна копия не остановлена предпроверкой. `✔️`, `➡️` и `⏩` код не портят.                                                                                                                                                       |
| `1` | Ошибка проверки параметров; [запрещённые аргументы](#запрещённые-аргументы); ошибка функции отбора или нет терминала при `--interactive` — по [резолверу](../../platform/git-working-copies-resolver.md); нет терминала при [пороге](../../platform/mass-confirm.md) без `--all`; `abort` на ошибке копии; `continue`, но копия не прошла предпроверку или в итоге был знак `❌` или `⚔️`. |
| `2` | Неверный вызов CLI (Cobra), если применимо.                                                                                                                                                                                                                                                                                                                                               |

## Инварианты

- На каждую копию прогона приходятся одни и те же `<from>`, `[to]`,
`--remote` и списки аргументов `git`.
- Локальная `<from>` удаляется только после успешного слияния, при
выключенном `--keep-source-branch` и только если ветка, на которой
копия останется, не равна `<from>`.
- Конфликт слияния остаётся в копии. Команда его не снимает.
- Повторов нет. `--retries-number` на ошибки копий не тратится.
